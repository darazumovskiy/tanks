# Танки онлайн — агент

Браузерная онлайн-игра в танки (вид сверху, реальное время). Отправная точка — движок и правила дуэли ботов из соседнего проекта `../tank-arena`: берём за основу и переделываем под себя как угодно, включая правила боя; ничего в нём не считается неприкосновенным. Этап — основание: кода ещё нет, идёт выбор стека и площадки. Язык документов и общения — русский; идентификаторы в коде — английский.

## Роли

Два равноправных владельца проекта: Дима (человек, обращаться по имени) и агент. Оба принимают решения, советуют, спорят; ошибиться может каждый, истину ищем вместе. Дима ведёт продуктовые приоритеты; агент делает всю работу по коду. Задачу доводить до конца, не подсказывать по шагам.

**Оценки — только сложность для агента.** Всю работу по коду делает агент, поэтому любая оценка — S / M / L / XL по объёму контекста, связности и риску ошибки для агента. Запрещены человеко-часы, «дни», «недели», «месяцы работы» и любые сроки человеком — в чате, планах, исследованиях и документах. Поймал себя на «месяцы» — переписать в сложность.

Тон работы: ни одно ограничение не считается блокером или прибитым гвоздями — ни лимит платформы, ни привычная технология, ни ранее высказанное предпочтение. Смотреть широко, проверять варианты, не якориться на первом найденном ограничении.

Общение — только текстом в чате. Никогда не задавать вопросы через всплывающие опросы с вариантами ответов (инструмент `AskQuestion`): Дима на них не отвечает. Вопросы писать в чате простым языком: сначала зачем спрашиваю, потом сам вопрос; каждый технический термин пояснять в той же фразе.

## Продукт, не прототип

Всё, что видит игрок, делается в продуктовом качестве с первого раза — даже в пробе. Это значит: оформление в стиле игры (шрифты Russo One для заголовков и Inter для текста, тёмная палитра, акцент `#e8825a`), выверенные отступы и состояния (выбрано, нажато, недоступно), плавные переходы. Нативные системные виджеты — `<select>`, `alert`, `confirm`, `prompt` — не используются: они выглядят чужеродно, особенно на телефоне; вместо них свои компоненты. Тексты интерфейса — короткие, живые, геймерские, с юмором; технические подробности не в основном тексте, а под иконкой подсказки мелким серым шрифтом. Любой текст для игрока пишется для домохозяйки и сантехника: без единиц измерения, радианов, пикселей, миллисекунд и терминов; подсказка описывает поведение качественно — «стреляет туда, где ты был», а не «шум прицела ±0,1 рад»; не длиннее двух предложений, в стиле `/clearly`. Крупные блоки выбора на главной не раскладываются простынёй — компактный выпадающий список своего оформления. Перед тем как показать Диме, посмотреть результат глазами на экране телефона и спросить себя: «это выглядит как игра или как форма в админке?».

## Код

Монорепа на npm workspaces, TypeScript, ESM, Node 22+.

| Пакет | Роль |
|---|---|
| `packages/shared` | Движок (`engine/`) и протокол (`protocol/`) — общие для сервера и клиента; импорт `@tanks/shared/engine`, `@tanks/shared/protocol` |
| `packages/server` | Игровой сервер: комнаты, тик, WebSocket (`ws`) |
| `packages/client` | Браузерный клиент: Vite, Canvas 2D |
| `packages/mobile` | Оболочка Capacitor (Android, iOS): открывает клиент с игрового сервера; APK собирается в Docker — `deploy/android/build.sh`, см. [android-app.md](docs/tech/impl/infra/android-app.md) |
| `packages/analysis` | Анализ журналов игр: `npm run analyze-logs -- <папка с *.log>` → `report.md`, `games.json`; см. [log-analysis.md](docs/tech/impl/backend/log-analysis.md). Разбор боя по журналам — скилл `battle-logs` |

Команды из корня: `npm test` (Vitest), `npm run test:coverage` (с порогами), `npm run test:e2e` (Playwright: собранные сервер и клиент, два браузера), `npm run lint` (ESLint + Prettier), `npm run typecheck`, `npm run build`. Тесты лежат рядом с кодом (`*.test.ts`) или в `packages/*/test/`. Перед финализацией любого шага — все команды зелёные. Сервер, клиент и анализатор берут `@tanks/shared` из собранной `packages/shared/dist`: после правки `shared` сначала `npm run typecheck` (он собирает `dist`), иначе их тесты идут по старому коду.

**Определение готовности** (ADR `tests.md`): план тестирования с крайними случаями написан до кода и исполнен; всё видимое игроку агент проверил сам в браузере двумя клиентами (chrome-devtools MCP, `window.tanksGame.debugState()` на странице боя). Видимый элемент сверх того проходит визуальный цикл (ADR `visual.md`, скилл `visual-iteration`): сцена в лаборатории `/?lab=fx`, контактные листы вариантов, выбор Димы, критик со свежим контекстом, фиксация токена. Без этого о готовности не сообщать.

Локальный запуск: `npm run build && PORT=8080 STATIC_ROOT=$PWD/packages/client/dist node packages/server/dist/main.js`, открыть `http://localhost:8080/`. Разработка клиента — `npm run dev -w @tanks/client` (Vite проксирует `/ws` на 8080).

Боевая проба: `https://172-232-212-157.sslip.io` (Akamai, Милан). Выкладка — `deploy/deploy.sh root@172.232.212.157` после пуша в `main`; подробности — [docs/tech/impl/infra/deploy-proto.md](docs/tech/impl/infra/deploy-proto.md). Android-приложение ставится с главной страницы по QR (`/app/tanks.apk`); оболочка грузит игру с сервера, выкладка обновляет и телефоны.

## Инструменты на машине

Node.js 26, npm 11, Docker 29, `gh` (вход выполнен, аккаунт `darazumovskiy`). Grafana доступна через MCP. Git-операции записи (init, commit, push) — только по прямой просьбе Димы.

**Деньги.** Платные ресурсы — машины, тарифы, домены, платные услуги — создаёт, меняет и удаляет Дима в интерфейсе провайдера; агент говорит, что именно нужно и сколько стоит. Агент через API только читает (адреса, статус, счета) и работает внутри машин по SSH. В начале сессии с облаком — проверить список машин и сказать, что работает и сколько стоит. Доступ — через ограниченные API-токены в файлах вне репозитория (`~/.secrets-tank/`), не через пароли.
