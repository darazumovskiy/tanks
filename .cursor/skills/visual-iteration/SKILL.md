# Визуальная итерация

Правила — `docs/adr/visual.md`, язык — `docs/tech/base/visual-language.md`, токены — `docs/tech/base/vfx-catalog.md`, устройство лаборатории — `docs/tech/impl/frontend/fx-lab.md`, приёмы — `docs/research/juice-canvas-2d.md`. Прочитать до начала.

Роли: агент делает всё — токен, сцены, варианты, листы, критика, страницу просмотра. Оператор пишет одну фразу-запрос, подтверждает бриф и выбирает по странице просмотра. Ползунки лаборатории оператор не трогает.

## Вход

Логика элемента принята и покрыта тестами. Если нет — сначала логика, цикл не начинать.

## Шаги

1. **Бриф** — 5–10 строк в чате: что элемент сообщает игроку, полоса яркости (телеграф / удар / статус / фон), на каком фоне живёт, рядом с чем (снаряды, танки, панели), что запрещено. Оператор подтверждает одной фразой.
2. **Референсы** — 3–5 ссылок или скриншотов с подписью «что брать» и 2 анти-референса. Сначала `research/`, потом веб.
3. **Токен** — объект стиля в модуле рендера (`packages/client/src/render/<элемент>Style.ts`): цвета по состояниям, толщины в CSS-пикселях экрана, альфы, частоты. Код отрисовки читает только его.
4. **Сцены** — `packages/client/src/fxLab/scenes.ts`: по одной на каждое состояние элемента плюс одна рядом с самым ярким соседом (снаряд в полёте). Каждая сцена должна показывать своё состояние в кадре ячейки (половина экрана вокруг элемента): хвосты, маркеры и соседи — внутри кадра. Детерминизм: время снаружи, случайность — с seed.
5. **Раунд** — `packages/client/src/fxLab/variants.ts`, новый элемент массива раундов: безопасный якорь (прежний вид или победитель прошлого раунда), заведомо плохой якорь (или «слишком» — отклонённое направление), 4–5 кандидатов. Первый раунд — направления («холодный», «трассер», «точки»), следующие — числа вокруг победителя по 2–3 осям.
6. **Листы** — при запущенном Vite: `ROUND=<id> npm run fx-sheets` → `lab-shots/round-<id>/` (в `.gitignore`): листы сцена × экран, ячейки 1:1 по вариантам, серые копии. Перед повторным чтением снимка в чат — новое имя файла: инструмент чтения кэширует картинки по пути.
7. **Критик** — отдельный саб-агент со свежим контекстом, read-only, получает листы, ячейки и `visual-language.md`: «Проверка по скриншоту» бинарно, парное сравнение с перестановкой порядка, ранжирование, блокеры, правки параметров. Блокеры закрыть, лист переснять; второй круг критика — только если блокеры были.
8. **Показ** — ссылка на страницу просмотра `/?lab=fx&view=review&round=<id>` (Vite `npm run dev -w @tanks/client`, порт 5173) и 1–2 картинки в чате для ориентира. Вопрос один: «что из этого выглядит как игра?». Выбор и формулировку направления — в `decisions.md`, `pick` раунда — в `variants.ts`.
9. **Следующий раунд** — по замечаниям оператора и осям критика; шаги 5–8. Победитель слабее безопасного якоря — раунд провален, варианты переделать.
10. **Движение** — анимированная сцена (флажок «идёт время») и бой с ботом на эмуляции телефона и на компьютере: смена состояний, появление, исчезание, кадры (`debugState().fps`, худший кадр).
11. **Фиксация** — победитель становится токеном по умолчанию; кандидаты закрытых раундов удаляются из `variants.ts`, остаются якоря и победитель; эталонный снимок сцены — `packages/client/test/e2e/visual/`; строка в `vfx-catalog.md`; новое правило — `visual-language.md`; документ фичи в `tech/impl/` — ссылка на токен и сцены.

## Выход

Готовность — по разделу «Готовность видимого элемента» в `docs/adr/visual.md`. Пока хоть один пункт не закрыт, о готовности не сообщать.

## Не делать

- Оценивать свой результат словами «выглядит хорошо» — только критик и оператор.
- Балльные оценки и автономные петли «критик → правка» дольше двух кругов.
- Варианты, отличающиеся одним числом, в первом раунде.
- Нарушать собственный язык в кандидатах (ядро тоньше 1,5 px, серый с альфой) — критик вернёт.
- Менять логику, движок, протокол внутри визуального цикла.
