# Ревизия сессий

Ревизия — только чтение: ни коммитов, ни слияний, ни удаления веток и папок. Что убрать или довести — в отчёте; своё агент доводит после «да» оператора.

## Окно

Окно называет оператор («за сутки», «с понедельника 10:00») — перевести в часы от текущего момента. Не назвал — 48 часов.

## Шаги

1. **Сессии.** `python3 .cursor/skills/session-audit/sessions.py --hours <окно>` из корня репозитория. Скрипт выдаёт чаты Cursor без саб-агентов и ручные сессии Codex: время, первый и последний запрос, последний ответ, папки ворктри, команды git-записи и выкладки. «Тишина» меньше 15 минут — чат, скорее всего, работает сейчас. Сессии Codex без пометки ручного запуска — ревьюеры и исполнители, запущенные чатами, — скрипт отбрасывает.
2. **Git.** Состояние репозитория и всех ворктри — блок ниже. Прод — коммит в `/opt/tanks` на сервере. Совпадает с `origin/main` — всё, что в `origin/main`, выложено.
3. **Хозяин каждого куска кода.** У каждой ветки, коммита вне `main` и незакоммиченного файла найти чат, который его оставил:
   - по пути ворктри и командам git из вывода скрипта;
   - `rg -l -F '<файл или папка>' ~/.cursor/projects/<путь workspace, где / и . — дефисы>/agent-transcripts` — какие чаты трогали;
   - по времени изменения файла против времени чатов.

   Файлы правятся последние минуты, а чата с ними нет — это работающий сейчас чат: его стенограмма дописывается с отставанием.
4. **Проверка слов агента.** «Не закоммичено», «жду ответа», «скажи, если коммитить» — сверить с `git log origin/main -- <файл>`: позже файл мог уйти в `main` чужим коммитом.
5. **Все просьбы оператора.** Скрипт показывает только первый и последний запрос. В чате, где работа не закрыта (код вне прода, «жду», «скажи, если…»), прочитать в стенограмме все запросы оператора: просьба, которую перебило следующее сообщение и которой нет ни в коде, ни в плане, — пункт «Ждёт сигнала».
6. **Классификация** — таблица ниже.
7. **Отчёт.**

## Git

```bash
git fetch --all --prune
git worktree list
git branch -a -vv --sort=-committerdate
git stash list
for b in <ветки и remotes/origin/* кроме main>; do
  echo "$b: впереди $(git rev-list --count origin/main..$b), позади $(git rev-list --count $b..origin/main)"
  git log --format='%h %ci %s' origin/main..$b
done
git -C <каждый ворктри> status --short
git status --porcelain | awk '{print $2}' | xargs stat -f '%Sm %N' -t '%m-%d %H:%M' | sort
ssh -i ~/.ssh/tanks_probe_ed25519 -o BatchMode=yes root@172.232.212.157 \
  'sudo -u tanks git -C /opt/tanks log -1 --format="%h %ci %s"'
```

Ветка, у которой 0 коммитов впереди `main`, уже влита — в отчёт идёт как мусор на удаление. Незалитая ветка — у неё нет `upstream` и нет ветки с тем же именем в `git ls-remote --heads origin`.

## Классификация

| Что в чате | Куда |
|---|---|
| Код вне `main` или вне прода: ветка, ворктри, незакоммиченное, незалитое | «Код не дошёл до прода» |
| Чат правит файлы прямо сейчас — даже если его код вне `main` | «Работает сейчас» |
| Договорились «делаем», агент ждёт сигнала, кода нет | «Ждёт сигнала» |
| Предложение агента, без которого задача сломана или не закрыта | «Ждёт сигнала» |
| Незакоммиченное, не идущее в игру: скиллы, правила, конфиги, разведка, картинки | «Мелочи» |
| В `main` и на проде, или только обсуждение и рассуждения агента | «Пропущено» — одной строкой со ссылками |

## Отчёт

В чат, не в файл. Первая строка — итог: сколько мест с невыложенным кодом, сколько чатов работает, сколько ждёт сигнала, сколько из них агент доводит сам. Дальше разделы в порядке таблицы классификации.

Пункт раздела:
- ссылка на чат `[суть задачи](<uuid чата>)`; у сессии Codex — путь к её файлу;
- где лежит: ветка, папка, сколько коммитов, залито ли, насколько отстаёт от `main`, когда трогали последний раз;
- что там по сути — для игрока и проекта, не перечень файлов;
- на чём остановился агент;
- кто доводит: **«берусь сам»** — работа готова и проверена, осталось влить, разрешить конфликты, выложить, убрать мусор; **«нужен оператор»** — и что именно: выбор варианта, продуктовое решение, незаконченная задача, тяжёлые файлы, чужой репозиторий.

После разделов — «Берусь сам»: порядок, в котором агент доведёт свои пункты, и что для этого спросить у оператора.

В конце — «Для процесса»: повторяющиеся причины, по которым работа застряла, если они видны.
