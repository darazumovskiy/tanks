# Процесс

Где живёт код и знания, кто что решает, как оцениваются работы.

---

## Роли
Равноправные владельцы проекта — люди команды и агент. Человек, который ведёт сессию с агентом, — оператор. Оператор и агент принимают решения, советуют, оспаривают решения друг друга; истина ищется вместе, ошибиться может каждый. Оператор ведёт продуктовые приоритеты; агент выполняет всю работу по коду, даёт оценки сложности и сроков. Агент не ждёт инструкций по шагам — доводит задачу до конца и объясняет конкретные решения.

Документы, скиллы и правила репозитория не называют людей по имени: человек в них — «оператор» или «игрок». Имя и профиль оператора живут в его личных правилах агента вне репозитория.

## Ограничение — не блокер
Любое техническое ограничение (лимит платформы, отсутствие привычной технологии) — вводная для проектирования, а не причина отбросить вариант. Код пишется через прослойки, которые позволяют менять хранилище, транспорт, площадку без переписывания логики.

## Код — в GitHub
Единственный репозиторий проекта. Коммиты и пуши — только по прямой просьбе оператора.

## Документы — в `docs/`, по разделам
Концепции — `docs/concept/`. Технический дизайн — `docs/tech/base/` (общий) и `docs/tech/impl/` (конкретные фичи). Правила — `docs/adr/`. Исследования — `docs/research/`. Задачи с контекстом и планами — `docs/workflow/<задача>/`. Новый документ создаётся только в одном из этих разделов; карта — `docs/README.md`.

## Документ — финальная форма
В концепте, тех-дизайне, ADR и планах — только принятое решение. Сравнение вариантов, аргументы, отвергнутые подходы — в `docs/research/`. Факт принятия решения с датой — в `decisions.md` текущей задачи.

## Оценка работ
Все работы по коду выполняет агент. Оценка — сложность для агента (объём контекста, связность, риск ошибки), не человеко-часы.

## Текущая задача ведётся скиллом `current-task`
Папка задачи — `docs/workflow/<задача>/` с `INDEX.md`, `state.md`, `decisions.md`, `knowledge/`. Указатель на текущую — `.cursor/tasks/current`.
