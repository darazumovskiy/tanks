# ADR — принятые решения

Короткие обязательные правила: как пишем код, как относимся к архитектуре, процессу, деплою. Соблюдаются при любой работе с кодом и документами проекта.

## Формат

Один файл — одна тема (`code-style.md`, `architecture.md`, …). Внутри:

```
# Тема

Одна строка: что покрывает файл.

---

## Название правила
Абзац: что делать / что запрещено / какой результат. Примеры — только если без них правило читается двояко.
```

Без альтернатив, без истории решения, без «почему». Причины живут в `docs/research/` и `docs/workflow/<задача>/decisions.md`.

## Жизненный цикл

- Новое правило появляется после согласия оператора и агента в обсуждении; в одиночку ADR не заводится.
- Правило устарело — переписывается или удаляется, не комментируется.
- ADR противоречит задаче — следовать ADR и явно сообщить о конфликте.
