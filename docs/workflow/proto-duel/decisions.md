Только подтверждённые обоими владельцами. Дата, что решили, что это меняет.

## 2026-10-02

- **Задача — проба: сервер с сокетом, браузерный и Android-клиент, дуэль 1 на 1 по ссылке.** Дима играет сам с собой. Меняет: этап 1 плана-карты сужен до дуэли; движок берётся из `tank-arena` без обобщения на N танков.
- **Площадка пробы — машина `tanks-echo-mil` (Akamai, Милан, $5/мес).** Парижская удаляется после дневного замера.
- **Репозиторий — `github.com/darazumovskiy/tanks`**, публичный, создан Димой. Монорепа: `packages/shared` (движок, протокол), `packages/server`, `packages/client`.
- **Транспорт пробы — WebSocket.** Слой транспорта изолирован от игровой логики для будущей замены.
- **Android — настоящее приложение, отдельным этапом.** Не браузер на телефоне. Этап включает выбор технологии, сборку и способ установки на телефон Димы без магазина. Начинается после рабочей браузерной дуэли.
- **Коммиты и пуши — по завершении каждого шага плана**, без отдельного вопроса. Промежуточные коммиты внутри шага — на усмотрение агента.
- **Почта в git для этого репозитория — `darazumovsky@gmail.com`** (почта GitHub-аккаунта).
- **Код-стайл TypeScript вписан в ADR `code-style.md`:** Prettier, strict без `any`, булевы условия, префиксы булевых, без вложенных тернарников, ESM с расширениями, тесты рядом.
- **План тестирования — до кода, сквозная проверка — агентом в браузере** (2026-10-02, после бага со счётчиком команд между раундами). Для каждой фичи: сценарии и крайние случаи по трём слоям — сервер, клиент, сквозной прогон; исполняется до объявления готовности. ADR `tests.md`, шаблон документа фичи в `tech/impl/README.md`.
- **Порядок работ:** шаги «репозиторий → движок → протокол → сервер → браузерный клиент → деплой» делаются одним блоком с проверкой на каждом шаге; мобильное приложение — после.
- **Шаг 7 закрыт:** три игры Димы, сеть и управление с клавиатуры устраивают.
- **Мобильная оболочка — Capacitor, один веб-клиент для Android и iOS.** Оболочка не хранит клиент внутри, а загружает его с игрового сервера: выкладка обновляет игру на телефонах без переустановки.
- **Установка на Android — APK на игровом сервере по постоянному адресу, QR-код на главной странице.** Подпись своим ключом из `~/.secrets/`. Телефоны Димы и жены — Android; с них начинаем.
- **iOS на этапе пробы — без установки.** Capacitor-проект для iOS создаётся, но не собирается и не выкладывается; платный аккаунт Apple не заводим.
- **Сенсорное управление — два плавающих стика.** Левый задаёт желаемый курс корпуса, клиент переводит его в газ и поворот (задний ход при большом расхождении, газ падает с ростом угла доворота); правый задаёт направление башни, у внешнего кольца — стреляет, пока держишь; короткий тап — одиночный выстрел. Сервер и протокол не меняются.
- **Общение — только текстом в чате, без всплывающих опросов** (вписано в `AGENTS.md`).

## 2026-10-03

- **Экран боя на телефоне: камера за своим танком с приближением.** Видимое окно ~1000×560 условных точек, одинаковое на телефоне и компьютере; поле заполняет экран без боковых зон; противник за кадром — стрелка по краю экрана. Панели — компактные по углам. Картинки танков — в высоком разрешении, плотность отрисовки — по экрану. Поле целиком на экране отменяется.
- **Проба в браузере телефона прекращается: сначала приложение, потом экран боя.** Два этапа: 8b — Android-приложение (Capacitor, клиент грузится с сервера, APK по QR); 8c — экран боя под телефон, который Дима увидит в установленном приложении без переустановки. Кнопка «на весь экран» для браузера не делается.
- **Управление стиками принято:** «работает, можно привыкнуть». Пороги и радиус не меняем до пробы на новом экране боя.
- **Экран боя с камерой принят; обзор — параметр.** На телефоне (устройство с касанием) по умолчанию видно 75 % высоты поля, значение меняется на главной (40–100 %) и хранится на устройстве. На компьютере камера не приближает: поле целиком, как раньше. Отменяет пункт «окно одинаковое на телефоне и компьютере».
- **Режим против манекена.** На главной две кнопки: «Создать дуэль» (ссылка человеку) и «Против манекена» — слабый случайный бот на сервере, комната по коду с префиксом `bot`. Протокол не меняется.
- **Свобода камеры — две настройки, по горизонтали и по вертикали** (умолчания 15 % и 35 %): одна доля на обе оси на широком экране заставляла подъезжать к противнику вплотную, прежде чем камера сдвинется.
- **Умолчания настроек — подобранные Димой на 14T Pro:** стик 40 px, мёртвая зона 0,07, кольцо огня 0,89, обзор 80 %, свобода камеры 0/0, догон 120 мс.
- **Камера дуэли на телефоне кадрирует бой** (2026-10-03, «сделай сам»): в кадре свой танк и противник с запасом, приближение до настройки «Максимальное приближение» (75 %; догон 300 мс, плавность 600 мс) ступенями с порогом 20 % и медленно (отдаление вдвое быстрее), отдаление до целого поля, нижняя треть экрана свободна под пальцы, приближённая камера центрирует пару даже ценой пустоты за полем («центр событий»), отдалённая — поле; свой танк не попадает в нижние углы экрана (ближе 32 % к боку и ниже 50 % высоты) — зоны пальцев, пустота за полем — только если свой танк уехал бы под стик. Ползунки свободы камеры и запасов убраны. На много игроков — те же функции с выбором целей по радиусу угрозы.
- **Камера на телефоне — по трём критериям (отменено следующим пунктом выше):** (1) свой танк не попадает в зоны пальцев (не ближе 25 % к боковым краям, не ниже 40 % от низа — настройки); (2) иначе показывать поле, а не пустоту; (3) без дёрганья. Отменяет «камера у края не прижимается»: пустота за полем — только когда без неё нарушается пункт 1.
- **Клиент переподключается сам** при разрыве сокета (фон приложения, выкладка); пауза 1–5 с, ошибка от сервера — без повторов.
- **Замолчавший клиент не управляет танком** (2026-10-03, по отчёту агента об инвариантах управления): сервер повторяет последнюю команду не дольше 15 тиков; клиент сбрасывает стики при уходе в фон.
- **Фильтры холста в каждом кадре не используются** (тень и «подбитый» вид заготавливаются один раз, подсветка выстрела — наложением), плотность отрисовки — до 2. Причина: подозрение на просадку кадров на телефоне при стрельбе в движении; подтверждение — замером на устройстве.
- **Вибрация и новые звуки — вне пробы.** Звук выстрела есть, другие звуки и вибрация на выстрел и урон не делаются; шаг 8e сводится к камере и управлению.
- **Покрытие сервера доводится до 100 % по ADR `tests.md`** в рамках пробы: события длинного раунда (аптечка, подбор, зона) покрываются тестами, защитные ветки на невозможные состояния либо покрываются, либо убираются.
- **Стенд сквозных тестов клиента делается в рамках пробы:** два браузера на локальном сервере под Playwright, сценарии нескольких раундов подряд, переподключения соперника, фоновой вкладки. Это единственный автоматический способ ловить баги уровня «счётчик команд между раундами».
- **Мягкий перезапуск при выкладке — вне пробы и вне MVP.** Нужен только когда игра выйдет на людей вне офиса; до тех пор выкладка рвёт активные игры, клиенты переподключаются сами.
- **Парижская машина `tanks-echo-par` удалена**; из платных ресурсов остаётся только `tanks-echo-mil` ($5/мес).
- **Камера на телефоне — набор стратегий с переключением в бою** (2026-10-03, вечер). Камера вынесена за интерфейс стратегии; делаются как минимум две — «за своим танком» с фиксированным масштабом (А из `research/camera-techniques.md`) и «кадрирование пары» с исправленными дефектами (Б); число вариантов не ограничено, хорошие идеи добавляются. Переключатель — в панели настроек в бою. Дима проверяет только пользовательский опыт, логику — не валидирует. Если хороших вариантов получается несколько, остаются все как выбор игрока. За полем рисуется оформленная кромка не уже 420 единиц — общая для всех стратегий. Доведение до готовности — без возврата к Диме: сценарные тесты, визуальная проверка скриншотами и в двух браузерах, при необходимости — дополнительные агенты.
