# План-карта

Этапы проекта от пустой папки до трёх направлений. Сложность — для агента: `S` — одна сессия, связный кусок; `M` — несколько сессий, есть зависимости; `L` — отдельная задача в `workflow/` со своим планом и исследованиями. Риск — где вероятны ошибки или переделки.

## Этап 1 — Проба: дуэль по ссылке

Задача: [proto-duel](proto-duel/INDEX.md). Дима играет сам с собой с компьютера и Android-телефона и чувствует отклик. Правила `tank-arena` как есть (два танка, поле целиком на экране), без лобби, авторизации, итогов и мониторинга. Всё сделанное — основа следующих этапов.

| Работа | Сложность | Риск |
|---|---|---|
| Репозиторий и каркас монорепы, движок в TypeScript с тестом детерминизма | S | — |
| Протокол: схема сообщений, бинарный кодек, тесты кодека | M | Ошибки упаковки проявляются как «телепортации»; нужны тесты туда-обратно |

| Клиент: рендер из `tank-arena`, ввод с клавиатуры и мыши, предсказание, интерполяция, счётчики задержки | L | Самая сложная часть для ощущения отклика |
| Мобильный ввод: джойстики, кнопка выстрела, полный экран | M | Ощущение на реальном телефоне |
| Деплой по ссылке с HTTPS на машине в Милане | S | — |
| Стенд сквозных тестов клиента: два браузера на локальном сервере (Playwright), сценарии нескольких раундов, переподключения, фоновой вкладки; планы тестирования для уже сделанного | M | Стабильность тестов реального времени |

## Этап 2 — Прототип для толпы

Движок на N танков, камера за своим танком, карта под N, простейший режим с возрождением; нагрузочный стенд с ответом «сколько комнат на ядро»; браузерные боты (настоящий клиент в headless-браузере под управлением бота, с записью видео).

## Этап 5 — Ладдер

Отдельная задача с исследованием прокачки и архитектуры общего мира. Не планируется до итогов этапов 3–4.

## Бэклог исследований

Темы, которые требуют отдельного исследования до любого кода. Каждая начинается с воспроизводимости: стенд или тест, который показывает проблему по требованию, — и только потом варианты решения.

| Тема | Отправная точка | Условие входа | Сложность |
|---|---|---|---|
| Устойчивость игры к неровной сети: команды и снимки приходят пачками, сервер выбрасывает «лишние» команды за тик, танк дёргается и прыгает назад | Разбор журнала реальной игры с телефона — [proto-duel/knowledge/jitter-dne5.md](proto-duel/knowledge/jitter-dne5.md) | Эмуляционные тесты сети: прослойка между клиентом и сервером с заданным джиттером, склейкой пакетов, паузами и потерями по сценарию; сценарии из журнала воспроизводятся тестом, метрики (поправка, пропущенные команды, замирания противника) считаются автоматически. Без этого исправления не проверить: вживую сбой не повторяется по желанию | L |
