# Бэкенд: базовый тех-дизайн

Серверная сторона игры. Технология сервера не выбрана — здесь зафиксированы устройство и контракты, не зависящие от языка. Выбор идёт в [задаче bootstrap](../../workflow/bootstrap/state.md), сравнение вариантов — в [исследовании](../../research/realtime-stack.md).

## Составные части

| Часть | Роль |
|---|---|
| Игровой сервер | Долгоживущий процесс. Держит комнаты, крутит тик симуляции, принимает ввод, рассылает состояние |
| Движок | Общий детерминированный модуль правил и физики (наследник `kit/arena/engine.js` из `tank-arena`) |
| Лобби и учётки | Вход через Google, создание комнаты и ссылки, список участников, итоги. Обычный HTTP API |
| Хранилище | Долговременное: пользователи, комнаты, итоги боёв. Быстрое: сессии, присутствие, кто где держит комнату. Доступ через прослойку, база заменяема |
| Сбор логов | Приёмник ошибок клиента и сервера, хранилище с поиском |

Игровой сервер и лобби могут быть одним процессом в MVP; граница между ними проводится в коде с первого дня.

## Масштабирование

Комната — единица работы: целиком в одном потоке. Много комнат — много потоков и процессов на машине; много машин — по регионам, рядом с игроками. Лобби знает, какой процесс держит какую комнату, и отдаёт клиенту адрес для прямого подключения. Внутри комнаты масштаба нет: её потолок — число игроков, которое один поток обслуживает в бюджете тика; это число измеряется нагрузочным тестом и становится верхней границей размера комнаты.

## Цикл тика

1. Взять у каждого игрока одну команду из его очереди (с порядковым номером команды): команды, которые сеть склеила в пачку, применяются по одной за тик; очередь короткая; одна команда в запасе гасит дрожание сети, а стойкий запас из двух и более, простоявший секунду, сливается — задержка ограничена и не копится.
2. Проверить каждую команду: диапазон значений, частота, живой ли танк, допустим ли выстрел по перезарядке.
3. Выполнить шаг движка для всех танков и снарядов.
4. Записать события тика (попадания, смерти, подборы).
5. Сформировать и отправить каждому клиенту его дельту состояния.

Тик фиксированный, 30 в секунду. Если тик не укладывается в бюджет — это сигнал в мониторинг, не повод пропускать симуляцию.

## Протокол

Два канала с разными требованиями:

- **Быстрый**: ввод игрока и снимки состояния. Бинарная упаковка, без подтверждения доставки: новое сообщение заменяет старое, потерянное не повторяется. Каждое сообщение несёт номер тика.
- **Надёжный**: вход в комнату, чат, итоги, смена настроек. Доставка и порядок гарантируются.

Если транспорт даёт только надёжную доставку, оба канала идут по одному соединению; «без подтверждения» тогда означает, что серверная логика не ждёт подтверждений и не хранит очередь на повтор. Слой транспорта отделён от кодирования сообщений: смена транспорта не трогает игровую логику.

Кодек сообщений — один модуль, общий для сервера и клиента; формат описывается схемой, из которой генерируются или проверяются обе стороны.

## Компенсация задержки

- **Своё предсказание.** Клиент применяет свой ввод к своей копии движка сразу, не дожидаясь сервера. Получив авторитетное состояние, сверяет и при расхождении переигрывает неподтверждённые команды.
- **Интерполяция чужих.** Чужие танки и снаряды рисуются с небольшим отставанием (один-два интервала рассылки) между двумя полученными снимками — движение плавное, без телепортаций.
- **Выстрел.** Снаряд — физический объект, не мгновенное попадание, поэтому серверу не нужно «отматывать» чужие позиции на момент выстрела. Сервер создаёт снаряд в тик получения команды и может продвинуть его на задержку клиента в разумных пределах; предел — настройка сервера.

## Валидация и доверие

Клиент присылает только намерения. Сервер отбрасывает всё, что выходит за диапазоны, приходит чаще лимита частоты или не соответствует состоянию танка. Число отброшенных команд по игроку — метрика в мониторинг: это и защита, и будущий вход для античита.

## Хранение

За время боя в базу ничего не пишется. По окончании — одна транзакция: итог боя, строки по игрокам. Агрегаты игрока (фраги за всё время, точность) — отдельная таблица, обновляется из итогов.

## Боты

Бот — тот же контракт, что в `tank-arena`: `init(info)`, `tick(state) → команда`. На сервере бот исполняется в изолированной песочнице с лимитом времени на ход. Не в MVP, но игровой сервер проектируется так, что источник ввода (сеть или бот) — взаимозаменяемая деталь.
