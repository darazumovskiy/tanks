# Клиент дуэли

Браузерный клиент: страница создания дуэли и страница боя. Код — `packages/client/src/`, сборка Vite, рендер Canvas 2D, оформление и звук перенесены из `tank-arena/viewer/`.

| Файл | Роль |
|---|---|
| `main.ts` | Маршрут: `/` — форма (ник, раскладка характеристик — `statsPicker.ts`, «Создать дуэль» → `/d/<случайный код>`, выпадающий список уровней бота и «В бой» → `/d/bot<уровень><случайный код>`, см. [bot-ladder.md](../backend/bot-ladder.md)) и блок с QR-кодом Android-приложения, если сервер раздаёт APK ([android-app.md](../infra/android-app.md)); `/d/<код>` — бой, `body.duel` запрещает прокрутку, подсказка про ориентацию, панель настроек ([touch-controls.md](touch-controls.md)), в браузере Android — плашка «Открыть в приложении» ([invite-link.md](invite-link.md)). `?admin=1` на любой странице включает админ-режим на устройстве ([aim-line.md](aim-line.md)). Ник, характеристики, уровень бота и признак админа — в `localStorage`. `window.tanksGame` — доступ для сквозных тестов |
| `game.ts` | Связка: сеть → предсказание → ввод → эффекты → звук → рендер; цикл кадров с фиксированным шагом ввода 30/с; отсчёт рисуется на холсте, итог раунда — DOM-попап (`roundEnd.ts`), DOM-оверлей — для «ждём соперника» (ссылка с кнопками «Копировать» и «Поделиться» — `invite.ts`, [invite-link.md](invite-link.md)) и ошибок |
| `roundEnd.ts` | Попап итога раунда: «ПОБЕДА!» / «ПОРАЖЕНИЕ» / «НИЧЬЯ» со стороны игрока, причина, счёт, фраза по силе соперника (для бота — по уровню из кода комнаты), конфетти при победе; зелёная «В бой» убирает попап, серая «Меню» ведёт на главную. Показывается на паузе между раундами, прячется со стартом следующего. Тесты — `roundEnd.test.ts` |
| `statsPicker.ts` | Раскладка характеристик на главной: четыре строки с подписью, что даёт характеристика, по пять делений; очков ровно десять — деления сверх остатка приглушены, старт недоступен, пока очки не розданы; пресеты «Универсал», «Броненосец», «Гонщик», «Снайпер», «Пулемёт». Хранится как прежде — четыре цифры в `localStorage`. Тесты — `statsPicker.test.ts` |
| `net.ts` | WebSocket, кодек протокола, `Ping`/`Pong` раз в секунду → сглаженная задержка туда-обратно. Текстовые сообщения (уведомление для ИИ-агентов, [protocol.md](../backend/protocol.md)) пропускаются. Разрыв не по нашей воле — переподключение с паузой 1, 2, 4, 5, 5… с и повторный вход в ту же комнату; возврат вкладки или приложения на экран — попытка сразу; ошибка от сервера (комната полна, версия протокола) — окончательна. Тесты — `net.test.ts` с поддельным сокетом |
| `diag.ts` | Журнал клиента: строки о снимках, вводе, кадрах, камере и сети копятся и уходят на сервер пачкой раз в секунду (`POST /log`), при скрытии страницы — маяком; каждая строка несёт оценку таймкода игры — [game-log.md](../backend/game-log.md). Тесты — `diag.test.ts` |
| `prediction.ts` | Своя копия движка с правилами раунда из `RoundStart.rules` ([round-rules.md](../backend/round-rules.md)): ввод применяется сразу, очередь неподтверждённых команд, при снимке — состояние сервера плюс переигрывание очереди. Свои снаряды рисуются из предсказания, чужой танк и чужие снаряды — интерполяция между двумя снимками с отставанием на два тика |
| `input.ts` | WASD / стрелки — корпус; мышь — башня (скорость поворота, доводящая башню до курсора за тик, не быстрее предела движка); левая кнопка или пробел — выстрел; M — звук. Касания — стики из `touch.ts` через `steering.ts`; источники башни по старшинству: активный правый стик → мышь → 0; предохранитель от своего рикошета (настройка) сдерживает выстрел, путь которого по расчёту движка (`traceShot` из `@tanks/shared/engine`) вернётся в свой корпус, см. [touch-controls.md](touch-controls.md) |
| `sfx.ts` | Синтезированные звуки Web Audio: выстрел, рикошет, попадание, взрыв, перехват, аптечка, отсчёт, тревога зоны. Контекст открывается первым нажатием |
| `render/camera.ts` | Камера за своим танком: окно фиксированной высоты, прижатие к краям поля, перевод координат, метка за кадром — [mobile-screen.md](mobile-screen.md) |
| `render/view.ts` | Шрифты, цвета сторон, утилиты |
| `render/art.ts` | Спрайты танков из SVG (сетка 64×64, растр 256 px, носом вправо), окрашенные в цвет стороны; отрисовка с тенью, вспышкой, отдачей, «подбитым» видом |
| `render/floor.ts` | Пол карты в двойном разрешении, рисуется один раз: текстура, сетка, площадки появления, стены с тенью, фаской и полосой |
| `render/effects.ts` | Частицы (искры, дым, вспышки, кольца, огонь, обломки), следы гусениц и подпалины на отдельном холсте, хвосты и свечение снарядов, всплывающие цифры урона, объявления («ПЕРВАЯ КРОВЬ», «САМ СЕБЯ!», «ЗОНА СУЖАЕТСЯ»), тряска и вспышка экрана |
| `render/renderer.ts` | Сборка кадра: мир через камеру (пол → следы → аптечки → зона → танки → линия выстрела ([aim-line.md](aim-line.md)) → снаряды → частицы → метки), затем в экранных координатах — панели по углам (свой слева), таймер и счёт, стрелка на противника за кадром, объявления, отсчёт, строка отладки, стики |

## Итог раунда и выход в меню

Кнопка «⌂» в левом верхнем углу под своей панелью ведёт на главную в любой момент боя. Итог раунда — попап по центру поверх холста: заголовок со стороны игрока («ПОБЕДА!» в акцентном цвете с конфетти, «ПОРАЖЕНИЕ» приглушённо, «НИЧЬЯ» серым), причина («противник уничтожен», «по оставшейся броне», «оба уничтожены», «равная броня»), счёт с подсветкой своего, фраза по силе соперника: человек — «Соперник повержен»; бот уровней 1–3 — «Разминка засчитана», 4–6 — «Это уже был бой», 7–8 — «Серьёзный противник. Серьёзная победа», 9 — «Ас повержен. Таких побед по пальцам», 10 — «Невозможное случилось. Скриншот — и в рамку». Внизу две кнопки: зелёная «В бой» убирает попап (следующий раунд сервер начнёт сам), серая «Меню» ведёт на главную. Попап живёт, пока сервер держит паузу между раундами, и прячется на `RoundStart`.

План тестирования:

| Слой | Сценарий | Ожидание |
|---|---|---|

| Клиент | поражение, ничья | заголовки «ПОРАЖЕНИЕ» и «НИЧЬЯ», конфетти нет |

## Откуда берутся эффекты

Все эффекты и звуки запускаются событиями из снимков сервера (`SnapshotEvent`): направление и признаки события лежат в `dx`, `dy`, `flags`. Локальное предсказание эффектов не порождает, поэтому дублей нет; задержка эффекта относительно собственного действия — половина задержки сети.

## Что показывает строка отладки

Строка начинается с идентификатора игры и таймкода (`4ZVW 01:32`) — та же пара крупнее стоит под строкой раунда вверху экрана; её игрок называет при разборе сбоя по журналу. Дальше четыре числа, каждое отвечает на свой вопрос. **К/с** — успевает ли устройство рисовать (норма — частота экрана). **Худший кадр, мс** — максимум длительности кадра за последнюю секунду: были ли рывки (16 — идеально, 33 — заметно, 50+ — рывок); среднее к/с их прячет. **Задержка, мс** — туда-обратно до сервера. **Поправка, px** — насколько сервер поправил свой танк на последнем снимке (0,0 — клиент и сервер считают одинаково; большие числа — дёргает не отрисовка, а расхождение с сервером). Тик сервера, число неподтверждённых команд и правила раунда (`rules`) — в `window.tanksGame.debugState()`.

## Ограничения пробы

При уходе соперника экран возвращается к ожиданию с той же ссылкой. При разрыве связи (фон приложения, выкладка сервера) клиент переподключается сам, раунд начинается заново; счёт комнаты сохраняется, если соперник остался. Фоновая вкладка не шлёт ввод: браузер останавливает цикл кадров. Шрифты Russo One и Inter грузятся с Google Fonts, без сети — системные.
