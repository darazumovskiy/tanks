# Стенд сквозных тестов

Вся игра целиком: собранные сервер и клиент, два настоящих браузера заходят по ссылке и играют. Ловит то, что не видят тесты сервера и модульные тесты клиента: рассинхрон состояния между раундами, переподключение, поведение после ухода соперника.

Запуск: `npm run test:e2e` — собирает пакеты и гоняет Playwright (Chromium без окна). Код — `packages/client/test/e2e/`, настройка — `playwright.config.ts` в корне.

## Устройство

| Файл | Роль |
|---|---|
| `server.ts` | Запускает `packages/server/dist/main.js` на свободном порту с `STATIC_ROOT` из `packages/client/dist` и дополнительным окружением из конструктора (серверные тумблеры вроде `WALL_SLIDE`, переключатели общей игры `FFA_*`), читает порт из вывода; отдаёт адрес страницы, порт и адрес игрового сокета; умеет остановить и поднять заново на том же порту. `APK_PATH` из окружения разработчика не наследуется: установщик Android добавил бы на главную код со ссылкой на случайный порт |
| `player.ts` | Игрок в браузере: открывает `/d/<код>` (с `query` — строкой запроса, например `?admin=1`), `/ffa/<размер>` или главную со своими ником, характеристиками и, если заданы, настройками (`settings` → `tanks.settings`) в `localStorage` и записями `sessionStorage` (`session` — например, пропуск общей игры), читает `window.tanksGame.debugState()` — дуэли и боя толпы (`ffaState`, ожидание экрана и состояния), находит видимые слои и кнопки интерфейса толпы, наводит башню в бою толпы мышью по углу, едет к точке клавишами (`driveTo`) или доворачивает на курс и держит газ (`driveOnHeading`), наводит башню мышью по формуле камеры из `debugState().camera`, открывает панель настроек клавишей и читает подписи флажков (`settingsCheckLabels`); с `isTouch` — контекст телефона 844×390 с эмуляцией касаний (`pointer: coarse`), касание кнопки авто-огня, касание-протяжка через `Input.dispatchTouchEvent` протокола отладки (`touchDrag`), касание с ведением пальца по шагам (`touchBegin` → `move`/`release`), ожидание курса корпуса с выборками (`waitForHeading`) |
| `duel.spec.ts` | Сценарии на сервере с умолчаниями |
| `wallSlide.spec.ts` | Сценарий на отдельном процессе сервера с `WALL_SLIDE=50` — [round-rules.md](../backend/round-rules.md) |
| `ffa.spec.ts` | Общий бой — раздел «Сквозные толпы» |
| `home.spec.ts` | Главная: иконка игры отдаётся сервером; «В общий бой» на первом экране телефона и компьютера ([ffa-client.md](ffa-client.md), K20); перезагрузка открытой главной после выкладки и переход в бой, начатый во время сверки ([android-app.md](../infra/android-app.md), «Открытая главная после выкладки») |
| `swarm.ts` | Сетевой рой ботов толпы отдельным процессом: `packages/server/dist/swarm/main.js --url <сокет сервера> --size <размер> --count <N>`; остановка — Ctrl+C, последние строки отчёта — в сообщение упавшего теста |
| `netProxy.ts` | TCP-посредник между браузером и сервером: пересылает и страницу, и соединение игры, поэтому страница открывается через его порт. Разрыв закрывает обе стороны, как пропавшая сеть; молчание — открытые соединения перестают пересылать, не закрываясь; пока включён отказ, новые соединения сразу закрываются |

Танк ведётся клавишами как человеком: `A`/`D` — доворот корпуса до курса на точку, `W` — газ, когда курс сошёлся; башня — положение мыши, выстрел — зажатая кнопка. Убийство ставится на карте «Полигон»: стрелок (орудие 5, перезарядка 5) едет на верхнюю полосу `y = 100` и стреляет вдоль неё по мишени (броня 0), которая стоит на той же полосе у своего края — между ними стен нет.

## План тестирования

| Сценарий | Ожидание |
|---|---|
| Два браузера заходят по одной ссылке | у обоих `debugState()` не `null`, стороны 0 и 1; `W` у первого двигает его танк, второй видит это движение |
| Два раунда подряд | стрелок убивает мишень на авто-огне; у стрелка попап «ПОБЕДА!», у мишени «ПОРАЖЕНИЕ», кнопка «В меню» ведёт на `/`; приходит второй раунд, попап скрыт, авто-огонь выключен (`roundIndex` 1, карта 1); ввод в новом раунде двигает танк — проверка бага со счётчиком команд между раундами |
| Соперник ушёл и вернулся | у оставшегося оверлей «Ждём соперника», `debugState()` — `null`; соперник открывает ссылку снова — раунд начинается, оба едут |
| Сервер перезапущен под открытыми страницами | оверлей «Связь потеряна…», затем оба клиента переподключаются сами, раунд начинается, ввод работает |
| Телефон: кнопка авто-огня | кнопка видна игроку с касанием и скрыта на компьютере; касание включает (`isAutoFiring` true), второй игрок видит снаряды; второе касание выключает, снаряды заканчиваются и за время дольше перезарядки новых нет |
| Телефон: разворот и бросок | левый стик вправо — танк едет вперёд; палец по кольцу за корму без провала к центру — `heading` приходит к π, на каждой выборке `me.speed ≥ 0` и `isReversing` false; палец через центр основания на противоположную сторону (позади танка) — `isReversing` true и `me.speed < 0`; после отпускания `isReversing` false |
| Предохранитель от своего рикошета | игрок с `hasRicochetGuard: true` наводит башню мышью перпендикулярно к ближнему краю поля и зажимает кнопку — за время дольше перезарядки снарядов нет ни у него, ни у соперника, `isShotGuarded` true; наводит по диагонали вверх-вправо — снаряды появляются, `isShotGuarded` false |
| Линия выстрела | игрок с `hasAimLine` и соперник встают на верхнюю полосу «Полигона», первый наводит башню мышью на соперника — `debugState().aimLine.state` становится `onTarget`, `isReturning` false; соперник уезжает за стену (330, 160) в (1350, 700) — `none`, линия есть; у соперника с выключенной линией `aimLine` — `null` |
| Огонь по цели | телефон с `?admin=1` и `hasZoneFire` стоит на точке появления; компьютер прячется за стену (330, 160) в (480, 200) через (1150, 450) и (900, 200); телефон тянет правый стик вправо — башня вдоль оси появления (угол 0) — и держит 2 с: снарядов нет ни у кого, `isZoneFiring` false; компьютер выезжает на ось появления (480, 450) — `isZoneFiring` true, снаряды видны обоим |
| Админ-режим | страница с `?admin=1` — в панели настроек (клавиша O) есть флажок «Подсказка упреждения»; у игрока без параметра — нет |
| Кнопка «⌂» в бою | адрес становится `/`, видна главная |
| Комната с манекеном | по ссылке `/d/bot01…` раунд стартует сразу, человек на стороне 1, имя соперника «Манекен», он двигается |
| Бот с главной | в выпадающем списке уровень 10, «В бой» → адрес `/d/bot10…`, бой начинается, соперник «ПАРАЛЛАКС-ASTRA» двигается |
| Скольжение вдоль стен (`wallSlide.spec.ts`, сервер с `WALL_SLIDE=50`) | `debugState().rules.wallSlidePercent` 50 у обоих; первый едет на верхнюю полосу, доворачивает на ≈ 26° к краю и держит газ — у края пять замеров подряд: `me.speed ≥ 100`, `correctionPx ≤ 2`; второй видит, как противник проехал вдоль края больше 50 px |
| Фоновая вкладка | вручную на устройстве (`knowledge/device-testing.md`): браузер без окна не останавливает таймеры фоновой вкладки |

## Эталоны кадра дуэли

Кадр боя, интерфейс дуэли и страницы вокруг неё сравниваются с эталонными снимками попиксельно. Эталоны ловят любое видимое изменение рендера; перестройка рендера обязана проходить их без пересъёмки.

### Устройство

| Файл | Роль |
|---|---|
| `packages/client/src/frameStand/` | Стенд кадров `/?lab=frames`: именованные кадры настоящими `Renderer` и `Effects` через ту же проводку кадра дуэли, что игра (`duelPresenter.ts`: старт раунда, снимки сервера, события, шаг эффектов, видимый противник, кадр с линией выстрела, интерфейсом и отсчётом). Снимки идут по тикам с пустым списком событий, события — через `applyEvent` по их возрасту; эффекты прошлого кадра стенд гасит сам перед стартом раунда. Стенд задаёт данные кадра, старт раунда, как его прислал бы сервер, и время эффектов; итоги раунда — настоящим `showRoundEnd` поверх страницы боя. `window.tanksFrames`: `frames` (идентификатор, вид, экраны), `ready()`, `show(frameId, screenId)`, `snapshot()` — PNG показанного кадра холста. Параметры `?frame=`, `?screen=`, `?seed=` |
| `visual/duelFrames.spec.ts` | Сверяет список кадров стенда со своим, снимает каждый кадр холста на каждом его экране прямым и обратным порядком и сравнивает с одним эталоном; итоги раунда, главная и ожидание соперника — настоящие страницы на общем `GameServer`. По каждому контексту браузера проверяет: ни одного запроса к `fonts.googleapis.com` и `fonts.gstatic.com`, файлы `/fonts/*.woff2` отданы сервером с кодом 200 |
| `visual/duelFrames.spec.ts-snapshots/` | Эталоны `<кадр>-<экран>-darwin.png` |

Кадр стенда — мир в момент снимка (карта, танки, снаряды, аптечки, время раунда, фаза), события с возрастом, поездки танков, касания стиков, настройки и кадрирование. История до снимка выводится из него же: событие моложе момента ещё не случилось — танк до попадания целее, до гибели жив, аптечка до подбора лежит, снаряд до выстрела не летит; танк с поездкой до её конца стоит позади точки кадра по своему курсу и едет. Снимки сервера идут в эффекты по тикам раунда, как в игре: следы гусениц и выцветание подпалин привязаны к номеру тика.

Экраны — из лаборатории (`FX_SCREENS`): телефон 844×390, плотность 2, касание; компьютер 1280×720, плотность 1. Интерфейс, стики и эффекты — на телефоне; поле — на компьютере, где камера показывает всё поле. Кадрирование — половина экрана вокруг точки поля (как в лаборатории), середина экрана (для камеры: сдвиг окна меняет картинку) или полоса экрана; кадрируется всё, что не требует экрана целиком.

Стенд не копирует значения и порядок вызовов игры: игра и стенд вызывают один модуль.

### Детерминизм

- **Время.** Перед кадром состояние эффектов гасится (шаг старше любой частицы и объявления, затем сброс), камера сбрасывается; история проигрывается шагами по 16 мс от самого старого события, снаряда или начала поездки до момента снимка. На каждом шаге — снимки сервера за прошедшие тики раунда, затем события, шаг эффектов; последние 40 шагов рисуются — линия выстрела и предохранитель доходят до полного вида, камера встаёт. Кадр не зависит от часов и от предыдущего кадра.
- **Случайность.** Стенд с `?seed=` подменяет `Math.random` генератором mulberry32 с этим зерном и возвращает последовательность к началу перед каждым показом; спека открывает стенд с постоянным зерном, руками открытый стенд с тем же зерном показывает те же кадры. Код рендера случайность не меняет. Порядок обращений к случайности — часть поведения рендера: перестройка обязана его сохранить.
- **Шрифты.** Файлы шрифтов лежат в клиенте (`public/fonts/`), страница не ходит в сеть за ними. До первого кадра стенд явно загружает все начертания подключённого набора. Набор шрифтов не подключился — `ready()` падает с ошибкой, а не рисует запасным шрифтом.
- **Спрайты.** Рендер не рисует танк, пока его спрайт не загрузился; у каждого рендера свои спрайты. До первого кадра стенд рисует пробный кадр на каждом рендере и ждёт, пока в центре башни обоих танков не окажется цвет стороны вместо тёмного пола.
- **Снимок.** Кадр холста — пиксели самого холста (`toDataURL`), без экранного масштаба. Кадр страницы — снимок окна в CSS-пикселях; CSS-анимации итогов раунда заморожены на возрасте кадра. Ссылка-приглашение закрыта маской: в ней порт сервера.

### Допуск

`maxDiffPixels: 0`, `threshold: 0`: любой отличный пиксель — падение; сравнение Playwright пропускает только пиксели сглаживания.

### Пересъёмка

Эталон пересъёмывается только при осознанной правке вида — правке токена или рисунка, видимой игроку и согласованной с оператором, — и только тех кадров, которые она меняет: разница каждого упавшего кадра просматривается глазами в отчёте Playwright, затем `npx playwright test packages/client/test/e2e/visual/duelFrames.spec.ts --update-snapshots` в том же изменении. Перестройка рендера, разделение модулей, перенос эффектов на номера танков — пересъёмка запрещена: эталоны совпадают как есть. Новый кадр добавляется в стенд и в список спеки, его эталон снимается на коде до правки. Обновление Playwright, Chromium или файлов шрифтов — отдельное изменение на неизменённом рендере: спека прогоняется до пересъёмки, разница каждого упавшего кадра просматривается глазами и объясняется в описании изменения, затем пересъёмка всех упавших кадров. Эталоны сняты под macOS; на другой системе снимаются отдельно.

### Вне эталонов

- Страницы и слои поверх боя: панель настроек, нажатая кнопка авто-огня, баннер «Открыть в приложении», подсказка «поверни телефон», оверлеи «Подключаюсь…» и «Связь потеряна…».
- Админские состояния: линия выстрела в состоянии упреждения, стик при огне по цели.
- Другие виды линии выстрела — их держат эталоны `aimLine.spec.ts`.
- Состояния интерфейса без своего кадра: значок выключенного звука, итоги раунда против бота, победа и поражение по времени; следы гусениц на заднем ходу.
- Экраны телефонов, кроме 844×390; отсчёт, объявления и стики на компьютере — тот же код, что на телефоне, в другом масштабе интерфейса; масштаб охраняют панели в `map-0`.

Эталоны толпы — свои у каждой части шага 7 (7b-2, 7b-3, 7c, 7d). Часть, которая меняет вид толпы по договору [ffa-client.md](ffa-client.md) — новый слой, правка подложки, строка внизу экрана, — пересъёмывает только кадры, которые эта правка меняет: разница каждого упавшего кадра просматривается глазами, правка называется в отчёте, затем `npx playwright test packages/client/test/e2e/visual/ffaFrames.spec.ts --update-snapshots`. Правка без видимого изменения по договору (перестройка кода, перенос модулей) проходит эталоны толпы без пересъёмки. Эталоны дуэли правка толпы не меняет. Новый кадр добавляется в стенд и в список спеки одновременно; его эталон снимается три прогона подряд одинаковым.
