# Протокол дуэли

Бинарный протокол между клиентом и сервером поверх одного WebSocket-соединения. Код — `packages/shared/src/protocol/`: [bytes.ts](../../../../packages/shared/src/protocol/bytes.ts) (писатель и читатель байтов), [messages.ts](../../../../packages/shared/src/protocol/messages.ts) (типы сообщений), [codec.ts](../../../../packages/shared/src/protocol/codec.ts) (кодирование и декодирование). Версия — `PROTOCOL_VERSION` (сейчас 7), клиент присылает её при входе; несовпадение — ошибка и разрыв. Сообщения общей игры (типы 16–22) — [ffa-server.md](ffa-server.md).

## Сообщения

Первый байт — тип. Числа — big-endian. Строки — байт длины и до 255 байт UTF-8, обрезка по границе символа.

| Тип | Направление | Поля |
|---|---|---|
| `Join` 1 | клиент → сервер | версия протокола, код комнаты, ник, характеристики (4 × u8), пропуск для возврата в общую игру (строка, пусто у нового игрока), бот ли (u8), номер общей игры из приглашения (строка, пусто — любая игра этого размера; в дуэли пусто) |
| `Input` 2 | клиент → сервер | `seq` u32 — порядковый номер команды; команда: газ, поворот, поворот башни (i8, шаг 1/127), выстрел (u8) |
| `Ping` 3 | клиент → сервер | время клиента f64 |
| `Welcome` 10 | сервер → клиент | сторона (0/1), код комнаты |
| `RoomState` 11 | сервер → клиент | два места: занято ли, ник |
| `RoundStart` 12 | сервер → клиент | `gameId` — идентификатор дуэли для журнала (строка, 4 знака), номер раунда, карта, тиков отсчёта, счёт, `rules` — правила раунда (u8: процент скольжения вдоль стен 0–100, [round-rules.md](round-rules.md)), два танка (ник, характеристики) |
| `Snapshot` 13 | сервер → клиент | тик раунда, `gameTick` — тиков с начала дуэли (таймкод журнала), `ackSeq`, `hasSpareInput` (u8: запас команд не нужен — клиент пропускает шаг ввода), конец раунда, победитель, причина, радиус зоны, два танка (x, y, курс, башня, скорость, hp, перезарядка, жив — f64/u8), снаряды (id, владелец, x, y, vx, vy, рикошетов осталось, был рикошет, возраст), аптечки, события тика |
| `Pong` 14 | сервер → клиент | время клиента, тик сервера |
| `Error` 15 | сервер → клиент | код (версия, комната полна, плохое сообщение, бездействие), текст |

Событие в снимке: вид (u8 из списка `shot, impact, ricochet, fizzle, clash, hit, death, bump, kitSpawn, pickup, zoneStart, roundOver`), сторона или 255, x, y, значение (f32: урон, угол, лечение), `dx`, `dy` (f32: направление снаряда при выстреле и попадании, нормаль стены при рикошете), `flags` (u8: сам себя 1, рикошет 2, зона 4, конец по времени 8). Эти поля нужны клиенту для искр, дыма и надписей; на исход боя не влияют.

## Квантование команды

Оси команды передаются как целое от −127 до 127. `quantizeAction` возвращает команду после такого округления; клиент предсказывает движение по ней, а не по сырому вводу — иначе его расчёт разошёлся бы с серверным.

## Подтверждение ввода

Принятые команды игрока ждут в очереди сервера; за тик применяется одна, самая старая, и её `seq` уходит в `ackSeq` снимка этому игроку — `ackSeq` всегда номер последней применённой команды. Клиент выбрасывает подтверждённые команды из своей очереди и переигрывает оставшиеся от состояния снимка. Команды с `seq` не больше уже принятого отбрасываются; больше `maxInputsPerSecond` (90) в секунду — тоже. В очереди сервера не больше 3 команд: при переполнении самая старая выбрасывается, её выстрел переходит к следующей; так же сливается стойкий запас — очередь, которая секунду не опускалась ниже двух команд, теряет самую старую; одна команда в запасе — защита от дрожания сети, сервер её не сливает; запас, который секунду ни разу не понадобился, сервер отмечает в снимке `hasSpareInput`, и клиент пропускает один шаг ввода. Номер выброшенной в `ackSeq` не появляется, клиент снимает её вместе со следующей подтверждённой. Подробности — [duel-server.md](duel-server.md), раздел «Тик».

## Размер

Снимок без снарядов и событий — 143 байта; каждый снаряд +43, событие +23. Два танка при 30 снимках в секунду — около 4–6 КБ/с на клиента.

## Таймкод

`gameTimecode(gameTick)` в `timecode.ts` переводит тики в «мм:сс»; одной функцией пользуются экран боя, журнал сервера и журнал клиента (`backend/game-log.md`).

## Тесты

`codec.test.ts`: каждое сообщение туда-обратно (`RoundStart` — со скольжением 0, 50 и 100; сообщения общей игры), байт правил (`rulesToByte`, `rulesFromByte`), квантование, обрезка строк, рост буфера, отказ на мусор, обрывки и порченые значения. `ffaEvents.test.ts`: каждое событие матча → событие снимка. `timecode.test.ts`: границы секунд и минут.
