# Сетевой рой ботов

Отдельная программа на Node запускает N [ботов толпы](crowd-bots.md); каждый входит в общую игру через сокет как обычный игрок и знает о бое только то, что сервер прислал ему по протоколу. Рой нужен для нагрузочного теста и замера шума боя: тик сервера, трафик на игрока, задержка, снаряды на экране. Игру для людей добирают серверные боты ([ffa-server](ffa-server.md), «Серверные боты»).

Для сервера бот роя — участник, как человек: его место серверный бот не занимает, а сам бот роя место никому не уступает. Серверных ботов вызывает только человек, поэтому игра из одних ботов роя идёт без них, как раньше. Ник бота роя — как у серверного: «Сержант [4]».

## Запуск

```
npm run build
npm run swarm -- --url wss://tankbattle.io/ws --size 30 --count 28
```

| Параметр | Умолчание | Что |
|---|---|---|
| `--url` | `ws://localhost:8080/ws` | адрес игрового сокета |
| `--size` | 30 | размер игры: 10, 30 или 50 |
| `--count` | размер − 2 | сколько ботов; уровни — пирамидой |

Боты входят по одному раз в 200 мс; подбор сервера складывает их в одну игру. Ctrl+C закрывает все соединения: сервер держит места 15 с и убирает ботов.

## Отчёт

Раз в 5 с — строка в консоль:

```
30/30 в игре · BNRS 01:39 · бой 1:12 · вход на бота 63 КиБ/с (макс 66) · снимков 30/с, пропусков 0 · пинг 54/85 мс · мозг 0,04/0,61 мс · рой 16 % ядра · тик сервера макс 9,8 мс · снарядов в окне 6,1/16 · урон из-за экрана 20 %
```

| Поле | Как считается |
|---|---|
| в игре | ботов с соединением и номером игрока / всего |
| игра | номер игры из `FfaWelcome` и таймкод по последнему `gameTick` снимка у её ботов — как в строке внизу экрана игрока; по ним ищется журнал игры на сервере (`/opt/tanks-logs/<номер>.log`, строки с `tc=`). До первого снимка — только номер; боты в нескольких играх — через запятую; в игре никого — поля нет |
| фаза | фаза из `FfaState` и время матча по тику снимка — у бота, который сейчас в игре; в игре никого — «нет игры» |
| вход на бота | байты всех сообщений сервера за 5 с: в среднем на бота в игре и максимум у одного бота |
| снимков, пропусков | `FfaSnapshot` в секунду на бота в игре; пропуск — разрыв в `gameTick` между соседними снимками одного бота внутри матча (на итогах снимков нет по замыслу) |
| пинг | от `Ping` до `Pong`: медиана и 95-й процентиль по ближайшему рангу |
| мозг | обработка одного снимка ботом — вид и решение: медиана и 99-й процентиль |
| рой | процессорное время процесса роя за 5 с — справляется ли машина |
| тик сервера | максимум `tickDurationMaxMs` из `/healthz` того же сервера за 5 с: сервер держит максимум за последнюю секунду, рой опрашивает его раз в секунду; ответа не было — прочерк |
| снарядов в окне | снарядов в окне обзора живого бота: среднее и максимум |
| урон из-за экрана | доля урона по ботам от стрелков, которых в момент попадания не было в окне обзора жертвы |

## Связь

| Событие | Что делает бот |
|---|---|
| Соединение открыто | `Join`: код `ffa` + размер, ник, характеристики, пропуск (пусто у нового), признак бота |
| Каждую секунду | `Ping`: в лобби и на итогах команд нет, а сервер закрывает соединение после 10 с тишины |
| От сервера ничего 5 с | связь пропала, а закрытие не дошло (смена сети): бот рвёт соединение сам и входит с пропуском — сервер отвечает на каждый пинг, живая связь так не молчит |
| Снимок, свой танк жив | команда; номера команд — с единицы на каждое соединение |
| `FfaMatchStart` | новый матч: мозг и зеркало снарядов — с нуля |
| Соединение закрылось без ошибки | через 1 с — вход с пропуском: в окне возврата это тот же игрок, после окна сервер примет как нового |
| Сервер недоступен | повтор через 1, 2 и 4 с, дальше раз в 5 с |
| `Error Idle` | вход заново новым игроком |
| Другая ошибка: `Replaced`, версия протокола, неверное сообщение | бот останавливается, текст ошибки — в консоль; остановились все — рой выходит |
| Текстовое сообщение | пропускается: игровой сервер шлёт только двоичные |
| Двоичное сообщение не по протоколу | не игровой сервер или другая сборка: бот останавливается с подсказкой проверить адрес и сборку, процесс роя не падает |

## Файлы

| Файл | Роль |
|---|---|
| `server/src/swarm/swarm.ts` | N ботов на сокетах `ws`: вход по одному, переподключение, отчёт, опрос `/healthz`; `formatReport` — строка отчёта |
| `server/src/swarm/main.ts` | Разбор параметров, запуск, Ctrl+C; вне покрытия, как `server/src/main.ts` |
| `package.json` (корень) | `npm run swarm` |

## План тестирования

**Рой и сервер — через настоящие сокеты** (`server/test/swarm.test.ts`). `createApp` и рой в одном процессе, настоящая карта `ffa10`, тик 10 мс — втрое быстрее настоящего, чтобы боты успевали ответить на каждый снимок; матч 20 с. Наблюдатель — тестовый клиент в той же игре. Обрыв сети — прокси в тесте между роем и сервером: разрыв закрывает обе стороны, как пропавшая сеть; пока прокси отказывает, новые соединения сразу закрываются; «заморозка» перестаёт доставлять данные открытых соединений, не закрывая их.

| Сценарий | Ожидание |
|---|---|
| 8 ботов в `ffa10` | в составе 8 игроков с признаком бота; ники «Имя [уровень]» — по уровням 2, 2, 1, 1, 1, 0 и 1; матч стартует по минимуму; серверных ботов нет |
| Бой | танки ботов едут, снаряды рождаются, за матч у ботов есть попадания. Убийства проверяет стенд толпы: при тике 10 мс задержка процесса под нагрузкой — уже несколько тиков, и короткий матч без убийств возможен |
| Окно обзора | каждый выстрел бота — когда в окне вокруг его точки обзора есть другой живой танк (запас 80 на задержку реакции). Карта `ffa10` мала: враги почти всегда в окне, поэтому слепой выстрел надёжно ловит стенд толпы на `ffa30` |
| Конец матча | итоги, затем следующий матч: боты играют без нового входа — номера те же, снова едут не меньше 6 из 8 |
| Отчёт после матча | 8/8 в игре, одна игра с номером и таймкодом, фаза — бой; трафик и снимки больше нуля, пропусков 0; пинг, мозг, снаряды в окне — числа; тик сервера — из `/healthz` |
| 28 ботов в `ffa30`, без старта | все в одной игре; по уровням 7, 6, 5, 4, 3, 2 и 1; в отчёте — номер игры без таймкода и фаза «лобби» |
| Тишина в лобби дольше порога (200 мс) | соединения ботов живы: `Ping` идёт |
| Короткий обрыв сети | боты возвращаются с пропуском: те же номера |
| Тихий обрыв: прокси заморожен, порог тишины 300 мс | бот замечает молчание, рвёт соединение и возвращается с пропуском: те же номера |
| Обрыв дольше окна возврата | боты входят новыми игроками: новые пропуски, в составе — только они |
| Клиент входит с пропуском бота | клиент получает номер бота; бот получает `Replaced`, остановлен и больше не входит; остановились все — рой закончен |
| Порог бездействия 3 тика | выкинутый бот входит заново новым игроком |
| Чужой сервер на адресе: текст и двоичное сообщение не по протоколу | текст пропущен, бот остановлен с подсказкой, рой закончен без падения |
| Рой стартует раньше сервера | пока сервера нет — отчёт без игры, пинга и тика сервера; сервер поднялся на том же порту — боты входят |
| Бот входит в идущий матч | едет |

Строка отчёта (`formatReport`) — на каждую фазу; игра — номером и таймкодом, до первого снимка — только номером, несколько игр — через запятую; адрес `/healthz` — из адреса сокета, `wss` → `https`; ответ без длительности тика и недоступный сервер — прочерк.

Замеры пинга и мозга копятся до отчёта; `npm run swarm` берёт отчёт раз в 5 с.

Клиента рой не меняет, проверки в браузере у него нет.

**Нагрузка — вручную агентом**, итоги — в `workflow/multiplayer/knowledge/snapshot-traffic.md`:

| Прогон | Что снять |
|---|---|
| Сервер и рой на машине оператора: `ffa50`, 50 ботов, матч целиком | трафик на бота, тик сервера, пинг, загрузка роя, шум выстрелов |
| Рой с машины оператора на боевой сервер: `ffa30`, 30 ботов, матч целиком | то же; матч доигрывается без обрывов и пропусков |
