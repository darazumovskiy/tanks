# Сервер дуэли

Один процесс Node: HTTP для клиента и проверки здоровья, WebSocket на `/ws`, комнаты по коду, общий тик 30/с. Код — `packages/server/src/`.

| Файл | Роль |
|---|---|
| `app.ts` | HTTP-сервер, апгрейд WebSocket, разбор сообщений, цикл тика с компенсацией дрейфа таймера, `/healthz` |
| `room.ts` | Комната: два места, фазы `waiting → countdown → fight → roundEnd → …`, снимки. Вход даёт `Seat` — ввод, ping и уход игрока идут через него; бой (`Duel`) существует только при двух игроках. Сокетов не знает — работает через `Connection.send` |
| `roomManager.ts` | Комнаты процесса, соединение → место и комната, удаление пустых; код с префиксом `bot` — комната с манекеном |
| `bot.ts` | Манекен: `Connection` внутри процесса — занимает место 0 при создании, получает те же сообщения, что игрок, отвечает вводом через своё `Seat` |
| `static.ts` | Раздача собранного клиента; `/` и `/d/<код>` отдают `index.html`; путь запроса для всех HTTP-веток |
| `main.ts` | Запуск: `PORT`, `STATIC_ROOT`, `APK_PATH` |

## Комната

Код комнаты — `[a-z0-9]{3,16}` из ссылки `/d/<код>`; комната создаётся при первом входе и удаляется, когда оба вышли. Третьему входящему — `Error RoomFull`. Ник обрезается до 16 символов, пустой — «Игрок»; неверные характеристики заменяются на 3/3/2/2.

Фазы: пока игрок один — `waiting`, снимки не идут. Два игрока — `RoundStart` и отсчёт 90 тиков, в отсчёте ввод игнорируется, снимки идут. Бой — до конца раунда по движку. После конца — 90 тиков паузы, счёт победителю, следующий раунд на следующей карте (`roundPlan`). Уход игрока в любой фазе — раунд сбрасывается, комната в `waiting`, счёт сохраняется.

## Манекен

Код комнаты, начинающийся с `bot` (кнопка «Против манекена» на главной генерирует `bot<случайный код>`), создаёт комнату, в которой первым игроком уже сидит манекен — ник «Манекен», характеристики по умолчанию. Человек получает сторону 1, раунд стартует сразу. Манекен слабый: каждые 1–2 с выбирает случайный курс и едет на 60 % газа (застрял — выбирает заново), башню ведёт на противника вдвое медленнее предела и с шумом до ±0,35 рад, стреляет с вероятностью 0,3 в секунду, когда наведён в пределах 0,3 рад. Его ввод проходит те же проверки комнаты, что и ввод игрока. Второму человеку в такую комнату — `RoomFull`. Ушёл человек — манекен снимается, комната удаляется; вход по той же ссылке снова сажает манекена. Случайность подменяема (`AppOptions.random`) — тесты детерминированы.

## Тик

Каждый тик: для каждого игрока берётся последняя пришедшая команда (остальные за тик теряются), её `seq` становится `ackSeq`; без новой команды повторяется предыдущая, но не дольше `INPUT_TIMEOUT_TICKS` (15 тиков, полсекунды) — замолчавший клиент (приложение в фоне, зависло) получает покой, а не вечную езду и стрельбу по последней команде. Шаг движка; снимок каждому игроку со своим `ackSeq`. Таймер — `setTimeout` от расписания, не от фактического времени; при отставании больше пяти тиков расписание сбрасывается. `/healthz` отдаёт число комнат, соединений, тик и максимальную длительность тика за последнюю секунду.

## План тестирования

Только через точки входа: HTTP и WebSocket (`test/client.ts` — клиент на том же кодеке). Скриптовые игроки шлют ввод на каждый снимок, как настоящий клиент. Покрытие `packages/server/src` без `main.ts` — 100 % по всем метрикам, порог в `vitest.config.ts`. Тики в тестах — 1–4 мс, отсчёт и пауза — 2–3 тика.

`app.test.ts` — HTTP, вход, одиночные действия:

| Сценарий | Ожидание |
|---|---|
| `/healthz` | 200, число комнат и соединений |
| Файлы клиента, `/`, `/d/<код>`, выход за корень, неизвестное расширение | файл, `index.html`, 404, `application/octet-stream` |
| APK: есть файл, `HEAD`, файла нет, маршрут не настроен | 200 с заголовками, длина без тела, 404, 404 |
| WebSocket не на `/ws` | соединение отклонено |
| Битый кадр WebSocket (без маски) | сервер закрывает соединение, `/healthz` живой |
| `createApp()` без параметров, `close()` без `listen()` | работает с умолчаниями, закрывается без ошибки |
| Два игрока входят | стороны 0 и 1, `RoomState`, `RoundStart`, одна комната |
| Повторный `Join` из комнаты | игнорируется: ни ошибки, ни второго `Welcome` |
| Третий в комнату, чужая версия протокола, неверный код, мусор, серверное сообщение от клиента | `Error` с кодом и закрытие |
| Пустой ник, неверные характеристики | «Игрок», 3/3/2/2 |
| Манекен (`bot…`) | сидит первым, двигается и стреляет, третьему отказ, уходит с человеком, комната удаляется |
| Уход игрока | `RoomState` без него, снимки прекращаются, пустая комната удаляется |
| Отсчёт и ввод | в отсчёте танки стоят; после — ввод двигает танк, `ackSeq` подтверждает |
| Клиент замолчал | танк останавливается |
| Устаревший и слишком частый ввод | отброшен; через секунду лимит сброшен и ввод снова принимается |
| Выстрел, рикошет о стену | снаряд, события `shot`, `ricochet`, `impact`/`clash` |
| Ping | `Pong` с тиком |
| Ввод и ping до входа | тишина |
| Процесс встал дольше пяти тиков | расписание сброшено: тики не навёрстываются пачкой |
