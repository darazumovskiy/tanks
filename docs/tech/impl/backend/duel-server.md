# Сервер дуэли

Один процесс Node: HTTP для клиента и проверки здоровья, WebSocket на `/ws`, комнаты по коду, общий тик 30/с. Код — `packages/server/src/`.

| Файл | Роль |
|---|---|
| `app.ts` | HTTP-сервер, апгрейд WebSocket, разбор сообщений, цикл тика с компенсацией дрейфа таймера, `/healthz`; соединение, от которого 10 с не пришло ни одного сообщения (клиент шлёт `Ping` раз в секунду), закрывается таймером вне тика — так обрыв без закрытия TCP становится обычным уходом |
| `room.ts` | Комната: два места, фазы `waiting → countdown → fight → roundEnd → …`, снимки. Вход даёт `Seat` — ввод, ping и уход игрока идут через него; бой (`Duel`) существует только при двух игроках. Сокетов не знает — работает через `Connection.send` |
| `roomManager.ts` | Комнаты процесса, соединение → место и комната, удаление пустых; код `bot<уровень>…` — комната с ботом лестницы на месте 0, код `twin…` — с двойником игрока |
| `bots/` | Боты дуэли: бот как `Connection` внутри процесса; `createBot` — мозг уровня из пакета `@tanks/bots`, текст скрипта бота Астры читается из файла — [bot-ladder.md](bot-ladder.md); `createTwin` — двойник игрока по файлу профиля соперника — [twin-bot.md](twin-bot.md) |
| `static.ts` | Раздача собранного клиента; `/` и `/d/<код>` отдают `index.html`; путь запроса для всех HTTP-веток. Файлы из `/assets/` (хеш содержимого в имени) — `Cache-Control: public, max-age=31536000, immutable`; остальное (`index.html`, иконки, шрифты `/fonts/`, `.well-known`) меняется под тем же именем — `no-cache` с `Last-Modified`, совпавший `If-Modified-Since` получает 304 без тела |
| `gameLog.ts` | Журнал игры в файлы `LOG_DIR/<gameId>.log` с буфером и сбросом по таймеру; приёмщик строк клиента `POST /log` — [game-log.md](game-log.md) |
| `main.ts` | Запуск: `PORT`, `STATIC_ROOT`, `APK_PATH`, `LOG_DIR`, `WALL_SLIDE` (процент скольжения вдоль стен 0–100 для всех комнат, без переменной — 50, [round-rules.md](round-rules.md)) |

## Комната

Код комнаты — `[a-z0-9]{3,16}` из ссылки `/d/<код>`; комната создаётся при первом входе и удаляется, когда оба вышли. Третьему входящему — `Error RoomFull`. Ник обрезается до 16 символов, пустой — «Игрок»; неверные характеристики заменяются на 3/3/2/2.

Фазы: пока игрок один — `waiting`, снимки не идут. Два игрока — `RoundStart` и отсчёт 90 тиков (`DUEL_COUNTDOWN_TICKS` из `@tanks/shared/engine`, его же берёт бой ботов в браузере), в отсчёте ввод игнорируется, снимки идут. Бой — до конца раунда по движку. После конца — 90 тиков паузы, счёт победителю, следующий раунд на следующей карте (`roundPlan`). Уход игрока в любой фазе — раунд сбрасывается, комната в `waiting`, счёт сохраняется.

Правила движка (`AppOptions.rules`) одни на процесс: комната создаёт каждый раунд с ними и кладёт их в `RoundStart.rules`, чтобы клиент предсказывал по тем же правилам — [round-rules.md](round-rules.md).

## Бот

Код комнаты `bot` + две цифры уровня + код (кнопка «Против бота» на главной) создаёт комнату, в которой первым игроком уже сидит бот выбранного уровня со своим именем и характеристиками — [bot-ladder.md](bot-ladder.md). Человек получает сторону 1, раунд стартует сразу. Ввод бота проходит те же проверки комнаты, что и ввод игрока. Код с префиксом `bot` без известного уровня — неверный код комнаты. Второму человеку в такую комнату — `RoomFull`. Ушёл человек — бот снимается, комната удаляется; вход по той же ссылке снова сажает бота. Код `twin` + код так же создаёт комнату с двойником игрока на месте 0 — «Двойник» со своими характеристиками ([twin-bot.md](twin-bot.md), «Соперник в игре»). Случайность ботов подменяема (`AppOptions.random`) — тесты детерминированы.

## Тик

Каждый тик: для каждого игрока из его очереди команд берётся одна, самая старая, её `seq` становится `ackSeq`; без новой команды повторяется предыдущая, но не дольше `INPUT_TIMEOUT_TICKS` (15 тиков, полсекунды) — замолчавший клиент (приложение в фоне, зависло) получает покой, а не вечную езду и стрельбу по последней команде. Очередь (`inputs.ts`, общая с общим боем) сглаживает дрожание сети: команды, которые сеть склеила в пачку, применяются по одной за тик — столько же шагов, сколько клиент предсказал. В очереди не больше `INPUT_QUEUE_LIMIT` (3) команд, поэтому команда ждёт своего тика не дольше 100 мс: пары и тройки, которыми склеивает команды сеть телефона, умещаются, а после паузы в сотни миллисекунд ждать всю пачку дороже, чем потерять её начало. При переполнении выбрасывается самая старая команда (строка журнала `input overflow`, метрика `reason="overflow"`), но её выстрел переходит к следующей и стреляет только в её тик — короткое нажатие огня не теряется и не повторяется. Одна команда в очереди после применения — запас против дрожания сети: тик задержки на сервере, который предсказание скрывает от игрока, но на который свой танк убегает вперёд снимков. Нужен он, только пока сеть дрожит: если `INPUT_SPARE_TICKS` (30 тиков, секунду) после каждого применения в очереди оставалась команда и ни одного тика без команды не было, запас ни разу не понадобился — снимок этому игроку несёт `hasSpareInput`. Клиент тогда пропускает один шаг ввода: команда не приходит один тик, сервер берёт запасную, запас уходит, ни одна команда не теряется ([ffa-client.md](../frontend/ffa-client.md), «Запас команд»). Сам сервер одну команду не сливает: слив двигал бы свой танк рывком при каждой команде у границы тика. Стойкий запас из двух и более команд задержку только копит: очередь, которая `INPUT_BACKLOG_TICKS` (30 тиков, секунду) после применения не опускалась ниже `INPUT_BACKLOG_MIN` (2), при следующей пришедшей команде теряет самую старую (`input backlog`, `reason="backlog"`, выстрел так же переходит) — запас возвращается к одной команде; отсчёт идёт с создания канала, поэтому пачка нового соединения не сливается. Новый раунд очищает очередь и начинает отсчёт слива заново. Шаг движка; снимок каждому игроку со своим `ackSeq` и `gameTick` — тиком с создания дуэли. Таймер — `setTimeout` от расписания, не от фактического времени; при отставании больше пяти тиков расписание сбрасывается; опоздание тика к расписанию передаётся в комнаты и попадает в журнал игры. `/healthz` отдаёт число комнат, соединений, тик и максимальную длительность тика за последнюю секунду.

Дуэль (`Duel`) при создании получает `gameId` — 4 знака без похожих символов; он уходит клиентам в `RoundStart` и именует файл журнала. Строки журнала сервера — в [game-log.md](game-log.md).

## План тестирования

Только через точки входа: HTTP и WebSocket (`test/client.ts` — клиент на том же кодеке). Скриптовые игроки шлют ввод на каждый снимок, как настоящий клиент. Покрытие `packages/server/src` без `main.ts` — 100 % по всем метрикам, порог в `vitest.config.ts`. Тики в тестах — 1–4 мс (кроме очереди команд), отсчёт и пауза — 2–3 тика.

`inputQueue.test.ts` — очередь команд, дуэль и общий бой. Тик — как на боевом сервере (33 мс): пачка команд, отправленная подряд, приходит в один тик. Слив и начало матча проверяются на ручном тике (`Room` и `FfaGame` без сокета, тик крутит тест): команды приходят ровно между тиками, и исход не зависит от скорости ответа клиента.
