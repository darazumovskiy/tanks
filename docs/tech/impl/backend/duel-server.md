# Сервер дуэли

Один процесс Node: HTTP для клиента и проверки здоровья, WebSocket на `/ws`, комнаты по коду, общий тик 30/с. Код — `packages/server/src/`.

| Файл | Роль |
|---|---|
| `app.ts` | HTTP-сервер, апгрейд WebSocket, разбор сообщений, цикл тика с компенсацией дрейфа таймера, `/healthz` |
| `room.ts` | Комната: два места, фазы `waiting → countdown → fight → roundEnd → …`, приём ввода, снимки. Сокетов не знает — работает через `Connection.send` |
| `roomManager.ts` | Комнаты процесса, привязка соединений, удаление пустых; код с префиксом `bot` — комната с манекеном |
| `bot.ts` | Манекен: `Connection` внутри процесса — получает те же сообщения, что игрок, отвечает вводом через `Room.input` |
| `static.ts` | Раздача собранного клиента; `/` и `/d/<код>` отдают `index.html` |
| `main.ts` | Запуск: `PORT`, `STATIC_ROOT`, `APK_PATH` |

## Комната

Код комнаты — `[a-z0-9]{3,16}` из ссылки `/d/<код>`; комната создаётся при первом входе и удаляется, когда оба вышли. Третьему входящему — `Error RoomFull`. Ник обрезается до 16 символов, пустой — «Игрок»; неверные характеристики заменяются на 3/3/2/2.

Фазы: пока игрок один — `waiting`, снимки не идут. Два игрока — `RoundStart` и отсчёт 90 тиков, в отсчёте ввод игнорируется, снимки идут. Бой — до конца раунда по движку. После конца — 90 тиков паузы, счёт победителю, следующий раунд на следующей карте (`roundPlan`). Уход игрока в любой фазе — раунд сбрасывается, комната в `waiting`, счёт сохраняется.

## Манекен

Код комнаты, начинающийся с `bot` (кнопка «Против манекена» на главной генерирует `bot<случайный код>`), создаёт комнату, в которой первым игроком уже сидит манекен — ник «Манекен», характеристики по умолчанию. Человек получает сторону 1, раунд стартует сразу. Манекен слабый: каждые 1–2 с выбирает случайный курс и едет на 60 % газа (застрял — выбирает заново), башню ведёт на противника вдвое медленнее предела и с шумом до ±0,35 рад, стреляет с вероятностью 0,3 в секунду, когда наведён в пределах 0,3 рад. Его ввод проходит те же проверки комнаты, что и ввод игрока. Второму человеку в такую комнату — `RoomFull`. Ушёл человек — манекен снимается, комната удаляется; вход по той же ссылке снова сажает манекена. Случайность подменяема (`AppOptions.random`) — тесты детерминированы.

## Тик

Каждый тик: для каждого игрока берётся последняя пришедшая команда (остальные за тик теряются), её `seq` становится `ackSeq`; без новой команды повторяется предыдущая, но не дольше `INPUT_TIMEOUT_TICKS` (15 тиков, полсекунды) — замолчавший клиент (приложение в фоне, зависло) получает покой, а не вечную езду и стрельбу по последней команде. Шаг движка; снимок каждому игроку со своим `ackSeq`. Таймер — `setTimeout` от расписания, не от фактического времени; при отставании больше пяти тиков расписание сбрасывается. `/healthz` отдаёт число комнат, соединений, тик и максимальную длительность тика за последнюю секунду.

## Тесты

`packages/server/test/`: через настоящий WebSocket (`client.ts` — тестовый клиент на том же кодеке). `app.test.ts` — HTTP, APK, вход, манекен (сидит первым, двигается и стреляет, третьему отказ, уходит с человеком), тайм-аут ввода (замолчавший танк останавливается), отказы, уход, движение, выстрел, спам ввода, ping. Скриптовые игроки в тестах шлют ввод на каждый снимок, как настоящий клиент. `duel.test.ts` — два скриптовых игрока доезжают до верхней полосы и доигрывают раунд до убийства: события, счёт, следующий раунд. Порог покрытия в `vitest.config.ts`; `main.ts` исключён.
