# Журнал игры

Диагностика сетевых и визуальных сбоев: каждая дуэль получает идентификатор, сервер и оба клиента пишут в один текстовый файл всё, что определяет движение и отрисовку танков. Игрок называет идентификатор и таймкод с экрана — агент читает файл вокруг этого момента.

Код: `packages/server/src/gameLog.ts` (файлы и приёмщик), `packages/server/src/room.ts` (строки сервера), `packages/client/src/diag.ts` (буфер и отправка с клиента), `packages/client/src/game.ts` (что клиент пишет). Формат строк читает анализатор `packages/analysis` ([log-analysis.md](log-analysis.md)): правка формата — вместе с ним. Как агент разбирает бой по журналу — скилл [battle-logs](../../../../.cursor/skills/battle-logs/SKILL.md).

## Идентификатор и таймкод

Дуэль (`Duel` в комнате) при создании получает `gameId` — 4 знака из алфавита без похожих символов (`23456789ABCDEFGHJKMNPQRSTUVWXYZ`). Раунды одной дуэли идут под одним идентификатором; уход игрока и новый вход — новая дуэль, новый идентификатор. Клиент получает его в `RoundStart.gameId`.

Таймкод — `gameTick`, число тиков с создания дуэли; в каждом `Snapshot`. На экране боя под строкой раунда: `ИГРА K7MF · 01:32` (минуты и секунды = `gameTick / 30`). Та же пара — в строке отладки внизу.

## Файл

`LOG_DIR/<gameId>.log` (на боевом сервере `LOG_DIR=/opt/tanks-logs`). Без `LOG_DIR` журнал не ведётся, приёмщик отвечает 404. Строки клиента до первого `RoundStart` (в бою толпы — до `FfaWelcome`) идут в `LOG_DIR/room-<код>.log`; код комнаты боя толпы — `ffa<размер>`.

Формат строки: `<время сервера по UTC HH:MM:SS.mmm> <источник> <текст>`. Даты в строке нет. Источник — `S` (сервер); `C0`, `C1` — клиенты дуэли по стороне; `C<номер игрока>` — клиент боя толпы, номер из `FfaWelcome` (до 65534, источник — до 6 знаков); `C` — клиент до входа в игру. Текст начинается с `gt=<gameTick> tc=<mm:ss.d>`, у клиента дальше `now=<мс>` — местные часы страницы; у клиента таймкод оценочный — последний снимок плюс местное время с его прихода. Время строки клиента — момент прихода пачки на сервер, а не момент события.

Запись на диск — не в тике: строки копятся в памяти и сбрасываются таймером раз в 500 мс (`appendFile`); при остановке процесса — синхронно.

## Что пишет сервер

| Строка | Когда |
|---|---|
| `game start room= p0= p1= rules=` | дуэль создана; `rules` — байт правил раунда, как в `RoundStart`: процент скольжения вдоль стен 0–100 |
| `round start idx= map= score=` | каждый раунд |
| `tick rt= ph= late= a0= ack0= in0= sil0= p0= a1= ack1= in1= sil1= p1= b=` | каждый тик дуэли: опоздание тика к расписанию в мс, применённая команда (газ, поворот, башня, огонь), подтверждённый `seq`, число команд, пришедших за тик, признак молчания, позиция и курс, число снарядов |
| `input stale side= seq= last=` / `input limit side= seq=` / `input overflow side= seq=` / `input backlog side= seq=` | команда отброшена как устаревшая, сверх лимита, самая старая в переполненной очереди или слита из стойкого запаса (очередь секунду не опускалась ниже двух команд) |
| `ev kind= side= x= y= v=` | событие движка: выстрел, попадание, рикошет, смерть, аптечка, зона, конец раунда |
| `leave side=` | игрок ушёл, дуэль закрыта |
| `loop late= dur=` | в файл `server.log`: тик опоздал к расписанию больше чем на тик или длился дольше 5 мс |

## Что пишет сервер общей игры

Журнал боя толпы не пишет поз: по нему бой повторяется прогоном движка ([ffaJournal.ts](../../../../packages/shared/src/protocol/ffaJournal.ts), `replayFfaJournal`) — сервер и разбор журналов исполняют один и тот же код. Ключ файла — номер игры (`FfaGame.id`), `gt` — тик игры.

| Строка | Когда |
|---|---|
| `game start mode=ffa size= rules=` | игра создана: размер (карта строится по нему) и байт правил |
| `join id= nick= bot=` / `rejoin id=` / `offline id=` / `quit id=` | вход, возврат по пропуску, обрыв соединения, выход кнопкой; `bot=1` — бот роя или серверный бот |
| `match start idx= players= seed= dur= roster=` | матч создан на начале отсчёта: сид, длительность в секундах, состав по порядку — `id:характеристики` через запятую (характеристики — четыре цифры: броня, мотор, пушка, перезарядка), у бота — с хвостом `:b`: `7:3322:b` |
| `fight start idx=` | отсчёт кончился; со следующего тика каждый тик игры — тик матча |
| `mjoin id= stats=` / `mjoin id= stats= bot=1` | человек / бот вошёл в идущий матч — в начале тика, до шага движка |
| `ac <id>=<газ>,<поворот>,<башня>,<огонь> … ` | команды, применённые в этом тике, у которых что-то изменилось с прошлого тика: оси — целые от −127 до 127, как в кодеке; `<id>=-` — команды нет (игрок без соединения стоит) |
| `death id= by= cause=` / `out id=` / `suddenDeath` / `matchOver` | события матча; `out` — бот выбыл в финале за человека и взорвался (без убийства и смерти в счёт) |
| `input stale id= seq=` / `input limit id= seq=` / `input overflow id= seq=` / `input backlog id= seq=` | команда отброшена — причины как в дуэли |
| `sum t= h=` | после шага движка, когда тик матча кратен секунде, и на последнем тике: тик матча и хэш состояния поля (`worldDigest`) |
| `leave id= reason=` | игрок убран: `offline` (обрыв дольше окна) и `yield` (серверный бот уступил место или ушёл вслед за последним человеком) — в начале тика, до шага; `idle` — после шага |
| `match over idx=` | матч кончился |

Прогон: матч создаётся по `match start` с признаком бота у игроков из состава, `leave` на отсчёте убирает игрока сразу; с тика после `fight start` на каждом тике — строки до шага в порядке журнала (выходы кроме `idle`, `mjoin`, команды из `ac`), шаг движка, сверка `sum`, выходы `idle`. Признак бота нужен прогону: по нему движок решает, кто выбывает в финале. Журнал без отметок ботов — бой одних людей, как и было до них.

Прогон верен кодом движка той же версии, что у сервера, писавшего журнал: после правки правил боя или расстановки старые журналы прогоняются кодом своего коммита, иначе расходятся с первой сверки.

Прогон совпадает с сервером побитово на процессоре той же архитектуры — x86, как боевой сервер. V8 на ARM (Mac, телефоны) считает `Math.sin`, `cos`, `atan`, `atan2`, `tan`, `exp`, `pow` иначе в последнем бите, поэтому прогон на ARM даёт редкие расхождения сверок: расходятся только скорости танков и снарядов в 15-м знаке, позиции, углы и исходы совпадают. Точная сверка — прогоном на сервере.

## Что пишет клиент

Клиент копит строки и отправляет пачкой `POST /log?key=<gameId>&src=<источник>` раз в секунду (`fetch` с `keepalive`), при скрытии страницы — `sendBeacon`. Тело — строки через `\n`, не больше 256 КБ; сервер добавляет время и источник.

| Строка | Когда |
|---|---|
| `device ua= screen= dpr= touch=` | старт |
| `net open` / `net close` / `net reconnect in=` / `net welcome side=` / `net room slots=` / `net roundstart game= idx= map=` / `net error` | события соединения |
| `vis hidden` / `vis visible` | вкладка или приложение ушли в фон и вернулись |
| `snap rt= gap= ack= pend= corr= me= srv= en= b= ev=` | каждый снимок: тик раунда, мс с прошлого снимка, подтверждённый `seq`, неподтверждённых команд после снимка, поправка в px, своя позиция после переигрывания, своя позиция в снимке, противник, число снарядов, события |
| `in seq= a=` | каждая отправленная команда |
| `in skip next=` | шаг ввода пропущен: сервер держит ненужный запас команд (`hasSpareInput`, [duel-server.md](duel-server.md), «Тик»); `next` — номер следующей команды |
| `shot seq=` | предсказание выпустило свой снаряд |
| `autofire on=` | игрок переключил кнопку авто-огня (1 — включил, 0 — выключил) |
| `flags guard= aimline= leadhint= zonefire= aimstyle=` | флажки настроек (предохранитель от своего рикошета, линия выстрела, подсказка упреждения, огонь по цели; 1 — включено, 0 — выключено) и идентификатор вида прицела: на старте каждого раунда и при любой смене в панели |
| `settings {…}` | полный снимок настроек игрока в JSON (стики, камера, флажки, вид прицела) — рядом с каждой строкой `flags`; по нему снимаются умолчания с реальных игр |
| `guard hold` / `guard cancel` | предохранитель начал сдерживать выстрел / сбросил отложенный тап по таймауту |
| `frame ms=` | кадр дольше 40 мс |
| `sec fps= worst= rtt= pend= snaps= ins=` | раз в секунду: кадров в секунду, худший кадр, задержка, очередь, снимков и команд за секунду |
| `cam mode= x= y= h=` | камера сменила режим или высота окна изменилась больше чем на 1 %; плюс раз в секунду |

## Что пишет клиент боя толпы

Отправка та же, источник — `C<номер игрока>`: с приходом `FfaWelcome` номер ставится на все ещё не отправленные строки, новый номер после потери места — на следующие. Снимков, команд, камеры и настроек клиент боя толпы не пишет — бой восстанавливается прогоном журнала сервера.

| Строка | Когда |
|---|---|
| `device ua= screen= dpr= touch= mode=ffa size=` | старт, в `room-ffa<размер>.log` |
| `net welcome id= game= outcome=` | вход в игру: номер игрока, игра, исход — `first` первый вход, `returned` возврат после обрыва, `lost` место ушло, вход заново |
| `net state phase= left= players= min= match=` | смена фазы: 0 лобби, 1 отсчёт, 2 бой, 3 итоги; тиков до конца фазы, игроков из мест, минимум, номер матча |
| `net matchstart idx= outcome=` | начало матча: `new` новый, `same` тот же матч после возврата |
| `net error code= text=` / `net disconnect retry= reason=` / `vis hidden` / `vis visible` / `close` | связь, фон, выход |
| `guard hold` / `guard cancel` / `autofire on=` | как в дуэли |
| `sec fps= worst= rtt= pend= snaps= ins=` | раз в секунду, как в дуэли |
