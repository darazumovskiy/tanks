# Журнал игры

Диагностика сетевых и визуальных сбоев: каждая дуэль получает идентификатор, сервер и оба клиента пишут в один текстовый файл всё, что определяет движение и отрисовку танков. Игрок называет идентификатор и таймкод с экрана — агент читает файл вокруг этого момента.

Код: `packages/server/src/gameLog.ts` (файлы и приёмщик), `packages/server/src/room.ts` (строки сервера), `packages/client/src/diag.ts` (буфер и отправка с клиента), `packages/client/src/game.ts` (что клиент пишет).

## Идентификатор и таймкод

Дуэль (`Duel` в комнате) при создании получает `gameId` — 4 знака из алфавита без похожих символов (`23456789ABCDEFGHJKMNPQRSTUVWXYZ`). Раунды одной дуэли идут под одним идентификатором; уход игрока и новый вход — новая дуэль, новый идентификатор. Клиент получает его в `RoundStart.gameId`.

Таймкод — `gameTick`, число тиков с создания дуэли; в каждом `Snapshot`. На экране боя под строкой раунда: `ИГРА K7MF · 01:32` (минуты и секунды = `gameTick / 30`). Та же пара — в строке отладки внизу.

## Файл

`LOG_DIR/<gameId>.log` (на боевом сервере `LOG_DIR=/opt/tanks-logs`). Без `LOG_DIR` журнал не ведётся, приёмщик отвечает 404. Строки клиента до первого `RoundStart` идут в `LOG_DIR/room-<код>.log`.

Формат строки: `<время сервера HH:MM:SS.mmm> <источник> <текст>`. Источник — `S` (сервер), `C0`, `C1` (клиенты по стороне). Текст начинается с `gt=<gameTick> tc=<mm:ss.d>`; у клиента таймкод оценочный — последний снимок плюс местное время с его прихода.

Запись на диск — не в тике: строки копятся в памяти и сбрасываются таймером раз в 500 мс (`appendFile`); при остановке процесса — синхронно.

## Что пишет сервер

| Строка | Когда |
|---|---|
| `game start room= p0= p1=` | дуэль создана |
| `round start idx= map= score=` | каждый раунд |
| `tick rt= ph= a0= ack0= in0= sil0= p0= a1= ack1= in1= sil1= p1= b=` | каждый тик дуэли: применённая команда (газ, поворот, башня, огонь), подтверждённый `seq`, число команд, пришедших за тик, признак молчания, позиция и курс, число снарядов |
| `input stale side= seq= last=` / `input limit side= seq=` | команда отброшена как устаревшая или сверх лимита |
| `ev kind= side= x= y= v=` | событие движка: выстрел, попадание, рикошет, смерть, аптечка, зона, конец раунда |
| `leave side=` | игрок ушёл, дуэль закрыта |
| `loop late= dur=` | в файл `server.log`: тик опоздал к расписанию больше чем на тик или длился дольше 5 мс |

## Что пишет клиент

Клиент копит строки и отправляет пачкой `POST /log?key=<gameId>&src=C<side>` раз в секунду (`fetch` с `keepalive`), при скрытии страницы — `sendBeacon`. Тело — строки через `\n`, не больше 256 КБ; сервер добавляет время и источник.

| Строка | Когда |
|---|---|
| `device ua= screen= dpr= touch=` | старт |
| `net open` / `net close` / `net reconnect in=` / `net welcome side=` / `net room slots=` / `net roundstart game= idx= map=` / `net error` | события соединения |
| `vis hidden` / `vis visible` | вкладка или приложение ушли в фон и вернулись |
| `snap rt= gap= ack= pend= corr= me= srv= en= b= ev=` | каждый снимок: тик раунда, мс с прошлого снимка, подтверждённый `seq`, неподтверждённых команд после снимка, поправка в px, своя позиция после переигрывания, своя позиция в снимке, противник, число снарядов, события |
| `in seq= a=` | каждая отправленная команда |
| `shot seq=` | предсказание выпустило свой снаряд |
| `frame ms=` | кадр дольше 40 мс |
| `sec fps= worst= rtt= pend= snaps= ins=` | раз в секунду: кадров в секунду, худший кадр, задержка, очередь, снимков и команд за секунду |
| `cam mode= x= y= h=` | камера сменила режим или высота окна изменилась больше чем на 1 %; плюс раз в секунду |

## План тестирования

Сервер — через сокет и HTTP (`packages/server/test/app.test.ts`, `duel.test.ts`):

| Сценарий | Ожидание | Статус |
|---|---|---|
| Два игрока входят | `RoundStart.gameId` — 4 знака алфавита; во втором раунде тот же; `Snapshot.gameTick` растёт на 1 между снимками и не сбрасывается новым раундом | авто |
| Игрок вышел и вошёл снова | новый `gameId` | авто |
| Дуэль с вводом и выстрелом при `logDir` | после закрытия сервера файл `<gameId>.log` содержит `game start`, `round start`, `tick` с `ack0=`, `ev kind=shot`, `leave` | авто |
| Устаревший `seq` и сверх лимита | строки `input stale`, `input limit` | авто |
| `POST /log?key=K7MF&src=C1` с двумя строками | 204; строки в `K7MF.log` с префиксом времени и `C1` | авто |
| Ключ или источник с недопустимыми символами | 400, файла нет | авто |
| Тело больше 256 КБ | 413 | авто |
| `POST /log` без `logDir` | 404 | авто |
| Сброс буфера по таймеру | строки появляются в файле без остановки сервера | авто |

Клиент (`packages/client/src/diag.test.ts`, happy-dom):

| Сценарий | Ожидание | Статус |
|---|---|---|
| Строки до и после `RoundStart` | до — ключ `room-<код>`, после — `gameId`; источник `C<side>` | авто |
| Таймер отправки | пустой буфер не отправляется; непустой уходит одной пачкой и очищается | авто |
| Страница скрывается | буфер уходит через `sendBeacon` | авто |
| Ошибка отправки | строки не теряются, уходят со следующей пачкой; буфер ограничен | авто |

Сквозной прогон (`npm run test:e2e`, сервер с `LOG_DIR` во временной папке):

| Сценарий | Ожидание | Статус |
|---|---|---|
| Два браузера играют | `debugState().gameId` одинаков у обоих; в файле есть строки `S`, `C0`, `C1` | авто |
| Экран боя | под строкой раунда виден `ИГРА <id> · mm:ss`, время идёт | вручную агентом в браузере |
| Бой с манекеном на боевом сервере | файл `/opt/tanks-logs/<id>.log` наполняется с телефона и сервера | вручную после выкладки |
