# Кто играет: визиты и устройства

Каждое открытие страницы игры оставляет на сервере одну запись визита: постоянный номер устройства, номер визита по счёту, откуда пришёл, язык и часовой пояс, железо и связь, IP, страна, город и провайдер. В бою к строке `device` журнала добавляется номер устройства, и анализатор склеивает игры с визитами: сколько людей, кто вернулся, откуда пришли. Потиковые данные визит не несёт: одна запись на открытие страницы, около килобайта.

## Схема

```
браузер  --POST /visit (JSON)-->  Caddy (X-Forwarded-For)  -->  игра: проверка полей, IP, гео  -->  /opt/tanks-logs/visits/<дата>.log
                                                                                                          <--tail--  Vector  -->  Grafana Cloud Logs (stream=visit)
бой: строка `device … dev=<номер>`  -->  журнал игры  -->  анализатор: раздел «Кто играл», visitors.json
```

## Клиент

Модуль [visitor.ts](../../../../packages/client/src/visitor.ts): номер устройства и профиль визита. Отправка — при загрузке главной, страницы дуэли и страницы боя толпы; лаборатории визит не шлют.

**Номер устройства** — 24 случайных знака `[a-z0-9]` из `crypto.getRandomValues`, хранится в `localStorage` под `tanks.device`. Там же — `tanks.visits` (счётчик визитов), `tanks.firstVisit` (время первого визита, ISO) и `tanks.firstFrom` (первая метка `from`, которую видело устройство). Испорченный номер заменяется новым, и счёт идёт с единицы; испорченный счётчик — визит 1. Хранилище недоступно (приватный режим Safari бросает исключение) — номер живёт до перезагрузки страницы, визит уходит с `visit: 1`.

**Метка источника** — параметр `?from=` в адресе любой страницы игры: `[A-Za-z0-9_-]{1,40}`, иначе не берётся. Первая увиденная метка устройства запоминается навсегда, текущая уходит в каждом визите.

**Профиль визита** — объект JSON, отсутствующее в браузере поле не отправляется:

| Поле | Откуда |
|---|---|
| `dev`, `visit`, `firstVisit`, `from`, `firstFrom` | номер устройства и метки |
| `page` | путь страницы: `/`, `/d/<код>`, `/ffa/30` |
| `nick` | сохранённый ник |
| `ref` | `document.referrer` — страница, с которой пришли |
| `ua` | строка агента браузера |
| `client` | описание клиента из [clientInfo.ts](../../../../packages/client/src/clientInfo.ts): платформа, оболочка, система, браузер, версии, экран, плотность пикселей, касание |
| `model`, `platformVersion` | `navigator.userAgentData.getHighEntropyValues` — модель телефона и точная версия системы; есть в Chrome и Edge, ждётся не дольше 1 с |
| `langs`, `tz`, `tzOffset` | `navigator.languages`, часовой пояс `Intl`, смещение от UTC в минутах |
| `cores`, `memory` | `navigator.hardwareConcurrency`, `navigator.deviceMemory` (гигабайты, округлены браузером) |
| `gpu` | название видеокарты из WebGL (`WEBGL_debug_renderer_info`); контекст сразу освобождается. Читается один раз на устройство и хранится в `tanks.gpu` (пустая строка — браузер название скрывает): на страницах боя WebGL рядом с запуском игры не создаётся |
| `net`, `downlink`, `rtt`, `saveData` | `navigator.connection` — тип связи, скорость, задержка, экономия трафика |
| `viewport`, `dark`, `reducedMotion` | размер окна, тёмная тема, просьба меньше анимации |

Отправка — `fetch` `POST /visit` с `keepalive`: «выстрелил и забыл», ответ не читается, ошибка сети или сбора профиля глотается.

**Плашка для игрока** — [privacyNote.ts](../../../../packages/client/src/privacyNote.ts), разметка `#privacy-note` в `index.html`: внизу главной, по центру, тёмная непрозрачная, в оформлении плашки «Открыть в приложении». Текст: «Запоминаем устройство, город и откуда ты пришёл — так видим, кто с нами играет. Город — по данным DB-IP», DB-IP — ссылка на `https://db-ip.com`. Крестик прячет плашку и пишет `tanks.privacyNoteClosed=1` в `localStorage` — на этом устройстве она больше не показывается; хранилище недоступно — плашка просто закрывается до перезагрузки. Пока плашка видна, у главной снизу запас 96 px, чтобы прокруткой вывести из-под неё последнюю кнопку. На страницах боя плашки нет.

## Сервер

Модуль [visits.ts](../../../../packages/server/src/visits.ts), ручка `POST /visit` в [app.ts](../../../../packages/server/src/app.ts). Без `LOG_DIR` ручка отвечает 404, как приёмщик журнала клиента.

**Проверка тела.** Тело больше 16 КБ — 413 (лишнее дочитывается впустую, как у `/log`). Не JSON, не объект или `dev` не по формату `[a-z0-9]{16,32}` — 400. Остальные поля — по белому списку с типом: строки обрезаются по длине поля, числа — конечные и в пределах поля, логические — только `true`/`false`; поле не того типа и незнакомые ключи выбрасываются. Ответ — 204.

**Частота.** Не больше 60 визитов в минуту с одного адреса и 20 000 в сутки (UTC) на весь сервер — около 40 МБ на диске и в Loki; сверх — 429, визит не пишется. Счёт — в памяти процесса: окно минуты общее, по его концу счётчики адресов сбрасываются.

**Адрес.** IP соединения; если соединение пришло от доверенного прокси (по умолчанию `127.0.0.1` и `::1` — Caddy на той же машине), берётся последний адрес заголовка `X-Forwarded-For`. Его дописал сам Caddy: без `trusted_proxies` в Caddyfile он заменяет пришедший заголовок адресом соединения, всё левее мог написать клиент. Встанет перед Caddy другой прокси (CDN) с `trusted_proxies` — последним адресом станет адрес этого прокси, и правило адреса нужно менять вместе с Caddyfile. Префикс `::ffff:` у IPv4 снимается.

**Гео** — [geo.ts](../../../../packages/server/src/geo.ts): офлайн-базы DB-IP Lite в формате MMDB, читаются библиотекой `mmdb-lib` из папки `GEO_DIR` при старте процесса целиком в память (база городов около 130 МБ, провайдеров около 10 МБ). Файлы — `dbip-city-lite.mmdb` (страна ISO, страна и город по-английски) и `dbip-asn-lite.mmdb` (номер автономной системы и название провайдера). Нет папки или файла, файл битый или недокачан — соответствующие поля пустые, битый файл — предупреждение в журнале процесса, сервер работает. Адрес не из базы или частный — гео пустое. Поиск — микросекунды, в обработчике HTTP, вне тика.

**Запись.** `visits/<ГГГГ-ММ-ДД>.log` в `LOG_DIR` (дата UTC) тем же буферизованным журналом, что журнал игры: строка `HH:MM:SS.mmm V {JSON}`. JSON — проверенные поля клиента плюс `at` (время сервера ISO), `ip`, `geo` (`country`, `countryName`, `city`, `asn`, `org`), `acceptLanguage` (заголовок, до 100 знаков).

## Журнал боя

Строка клиента `device` дуэли и боя толпы заканчивается номером устройства: `device ua=… screen=… dpr=… touch=… dev=<номер>` и `… mode=ffa size=30 dev=<номер>` ([game-log.md](game-log.md)).

## Анализатор

Модуль [visitors.ts](../../../../packages/analysis/src/visitors.ts). Читает `<папка>/visits/*.log` и строки `device … dev=` из `room-*.log` — туда клиент пишет строку `device` и дуэли, и боя толпы. Битые строки пропускаются. По каждому устройству: первый и последний визит по местному времени, число визитов, дней с визитами, открытий боя дуэли и толпы (одна строка `device` — одно открытие страницы боя), ники, место (страна, город), провайдер, IP, устройство (система, модель, браузер, приложение), языки и часовой пояс, источник. Источник — первая метка `from`; без неё — сайт из `ref` первого визита; без него — «прямой заход». Вернувшийся — устройство с визитами в разные местные дни. Устройство, у которого есть бой, но нет визита, попадает в сводку с нулём визитов. Журналы комнат сервер хранит 7 дней, визиты — 90: у давних устройств боёв в сводке меньше, чем было, отчёт об этом пишет.

Отчёт — раздел «8. Кто играл» в `report.md`: строка итога (устройств, визитов, вернувшихся, с боем), таблицы по странам и источникам, таблица устройств — свежие первыми. Черта и перевод строки в ячейках (ник задаёт игрок) экранируются. Данные — `visitors.json` рядом с отчётом. Ни визитов, ни строк с номером — раздел пишет, что визитов нет.

## Выкладка

- `deploy/tanks.service` — `Environment=GEO_DIR=/opt/tanks-files/geo`.
- `deploy/geo-update` — скачивает `dbip-city-lite-<ГГГГ-ММ>.mmdb.gz` и `dbip-asn-lite-<ГГГГ-ММ>.mmdb.gz` с `download.db-ip.com/free/` (текущий месяц, иначе прошлый), распаковывает во временный файл и подменяет файл в `/opt/tanks-files/geo` переименованием. Если база обновилась, перезапускает игру: сервер читает её только при старте. Копия лежит в `/etc/cron.monthly/tanks-geo-update` — `run-parts` зовёт её без аргументов, раз в месяц. `deploy-local.sh` кладёт копию и, если баз ещё нет, запускает скрипт с `--no-restart` (игру он перезапустит сам, ошибка скачивания выкладку не роняет).
- `deploy/tanks-logs-cleanup` — журналы игр старше 7 дней (только корень `/opt/tanks-logs`), визиты старше 90 дней.
- `deploy/vector/vector.yaml` — источник `visit_files` по `/opt/tanks-logs/visits/*.log`, поток `stream=visit`, тело — JSON визита. Меток, кроме `app` и `stream`, нет: страна, город и устройство фильтруются в запросе (`| json | geo_country="RU"`). Loki хранит визиты 14 дней (срок бесплатного тарифа Grafana Cloud), полные визиты — на машине 90 дней.
- Caddy передаёт `X-Forwarded-For` по умолчанию; `/visit` идёт в игру общим маршрутом.

Лицензия DB-IP Lite — CC BY 4.0, требует упоминания DB-IP со ссылкой: оно в плашке на главной.
