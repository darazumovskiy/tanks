# Анализ журналов игр

Инструмент, который по файлам журнала (`game-log.md`) считает, как игрок стрелял, наводился и двигался, и сводит игры в таблицу «устройство × уровень бота». Нужен, чтобы после каждой правки управления сравнивать серию с телефона и серию с компьютера числами, а не ощущениями (`workflow/proto-duel/knowledge/phone-vs-pc-logs.md`). Запускается на рабочей машине по скачанной папке журналов; в будущем те же метрики могут считаться на сервере.

Пакет: `packages/analysis` (`@tanks/analysis`), Node, зависит только от `@tanks/shared` (константы движка, геометрия, карты, характеристики, уровни ботов); профилей ботов сервера не знает. Запуск из корня: `npm run analyze-logs -- <папка с *.log> [--out <папка>] [--tz 3] [--only ID1,ID2]`. Результат: `<out>/report.md` и `<out>/games.json`; по умолчанию `<папка>/../analysis`. Точка входа для кода — `analyzeLogs(папка, { outDir, tzHours, only })` из `@tanks/analysis`: возвращает пути к файлам, разборы игр и список пропущенных файлов; CLI и стенд e2e зовут её напрямую.

## Что читает

Файлы `<gameId>.log` (строки `S`, `C0`, `C1`) и `room-<код>.log` (строки клиента до первого раунда — оттуда `device`). Строка: `HH:MM:SS.mmm <источник> gt=<тик> tc=<таймкод> [now=<мс>] <текст>`. Из серверных строк: `game start room= p0= p1=`, `round start idx= map= score=`, `tick rt= ph= late= a0= ack0= in0= sil0= p0= a1= ack1= in1= sil1= p1= b=`, `ev kind= side= x= y= v=`, `input stale|limit|overflow|backlog side=`, `leave side= nick=`. Строки тика и события до первого `round start`, строки без обязательных полей и строки не по формату пропускаются; файл без `game start` или без раундов пропускается целиком. Из клиентских: `device ua= screen= dpr= touch=`, `net roundstart`, `net room slots=`, `in seq= a=`, `autofire on=`, `sec fps= worst= rtt=`.

Формат строк — контракт между `room.ts`, `diag.ts` и анализатором: правка формата сопровождается правкой анализатора и его тестов.

## Что считает

**Сторона человека** — та, от которой есть строки клиента; если клиентские строки есть у обеих — та, чьё имя не из списка имён ботов (`BOT_LEVEL_INFO`). **Уровень бота** — из кода комнаты `bot<NN>…`, запасной путь — по имени бота. **Устройство** — строка `device` из `room-<код>.log` ближайшая по времени к старту игры (не дальше 5 минут), запасной путь — по нику из `net room slots=`; подпись: `Android (<модель>), касание` / `Mac, Chrome, мышь` / начало user agent.

**Характеристики по журналу** (строки старта их не пишут): скорость снаряда — по расстоянию от дула до первого рикошета или удара о стену этой стороны (медиана не меньше чем по трём измерениям, округление к ближайшей скорости из `deriveStats`; меньше трёх измерений — снаряд билда по умолчанию, 550, для обеих сторон); попадания в противника для измерения не годятся — у попадания в журнале нет владельца снаряда. Максимальная скорость — самая частая установившаяся скорость выше 100; перезарядка — минимальный интервал между выстрелами; здоровье — сумма полученного урона минус лечение в раундах со смертью. Уровни характеристик — ближайшие по `deriveStats` к измеренным величинам.

**Прослеживание снарядов.** Каждый `ev shot` рождает снаряд с углом башни из строки тика того же `gt` (в событии угол округлён до 0,1 рад); события `impact`, `fizzle`, `ricochet`, `clash`, `hit` сопоставляются ближайшему живому снаряду в допуске `2·скорость·DT + 15`; при рикошете направление отражается от нормали ближайшей преграды; попадание без снаряда после `zoneStart` с уроном ≤ урона зоны за тик — зона, иначе «неизвестно». Отсюда — попадания, самопопадания, рикошетные попадания, урон нанесённый и полученный, урон от зоны.

**Выстрелы человека.** В момент выстрела: дистанция, скорость противника (по соседним тикам), угловая ошибка башни к текущему положению и к точке упреждения (`leadPoint` как у ботов, четыре итерации), угловой размер танка `atan(24 / дистанция)`, прямая видимость (отрезок до противника не пересекает стен, раздутых на радиус снаряда). Класс выстрела: по стоящему (скорость ≤ 30) — «в цель» / «мимо»; по движущемуся — «упреждение», «текущее», «мимо обоих» (какая из ошибок меньше и укладывается ли в размер танка). Доля упреждения `(башня − направление на корпус) / (упреждение − направление на корпус)`.

**Наведение по тикам боя:** ошибка башни к противнику при прямой видимости (медиана, доля тиков < 5°); время наведения — тиков от ошибки > 30° до < 5°.

**Движение:** доля тиков с |газ| > 0,9, задний ход (газ < −0,05), простой (газ и поворот 0), средняя скорость, удары о стены (`ev bump`), тики молчания, команды сверх одной, пришедшие за тик пачкой (`in` > 1; поле `batched_inputs`, в отчёте «пачкой»), отброшенные (`input stale|limit|overflow|backlog`); гистограммы осей газ / поворот / башня по корзинам `0`, `<0,3`, `0,3–0,7`, `0,7–0,99`, `±1`.

**Динамика:** смены хода вперёд↔назад в минуту и тиков до разгона > 30 в новую сторону; резкие остановки (> 120 → < 30 за ≤ 10 тиков); развороты > 90° и их длина; кайтинг (скорость > 80, башня и противник сзади относительно движения); кружение (скорость > 80, дистанция меняется < 2 за тик, пеленг > 0,6° за тик); доля времени ближе 150 и 60 единиц к стене; средняя дистанция до противника.

**Клиентские команды:** смен знака поворота в минуту, из них ±1 → ∓1; доля команд, где поворот или газ изменились.

**Самопопадания человека:** для каждого — расстояние по лучу от дула до преграды, угол к нормали, дистанция и видимость противника, ошибка башни к нему, стоял или ехал в стену, был ли включён авто-огонь (по строкам `autofire` и `net roundstart`), полёт до возврата. Класс: «целился, но стена ближе» (ошибка < 15° и стена ближе противника), «в упор в стену без цели» (не целился, стена ближе 200), «рикошет издалека вернулся».

**Раунд:** победитель, причина (убийство / время / прерван), длительность боя, первое попадание каждой стороны, выстрелы и попадания, дистанция и доля видимости.

## Отчёт

`report.md`: (1) паспорта игр — время, комната, уровень, устройство, ник, раунды, счёт, характеристики, сеть; (2) сводка «уровень × устройство» (группа — уровень и устройство до первой запятой; игры без уровня и без выстрелов человека не входят): счёт, билды, попадания человека и бота, по стоящему / движущемуся, упреждение, ошибка башни, доля тиков без управления башней, время наведения, газ / скорость / задний ход, удары о стены, видимость, дистанция, самопопадания, сеть; (3) самопопадания по группам: число, доля выстрелов и урона, типы, геометрия; (4) динамика и команды по группам; (5) выигранные и проигранные раунды по устройствам (уровни ≥ 4); (6) контроль качества: измеренные характеристики, попадания без снаряда, снаряды без исхода, источник устройства; (7) прогон журналов боя толпы ([Бой толпы](#бой-толпы)). Игры в отчёте и JSON идут по местному времени старта, сутки отсчитываются с полудня — ночная серия после полуночи идёт за вечерней. `games.json` — массив игр: все числа по играм и раундам без строк выстрелов и самопопаданий.

Имена метрик в JSON — те, на которые ссылается таблица порогов в `knowledge/phone-vs-pc-logs.md` (`hit_pct_human`, `aim_err_median_deg`, `lead_share_pct`, `shots_moving`, `movement.*`, `dynamics.*`, `client_inputs.*`, `self_hits.*`); это контракт файла, в коде он описан типом `GameSummary`.

## Бой толпы

Журнал боя толпы (`game start mode=ffa`, формат — [game-log.md](game-log.md), «Что пишет сервер общей игры») прогоняется движком через `replayFfaJournal` из `@tanks/shared/protocol`: по составу, сиду, входам, выходам и командам каждый тик матча восстанавливается побитово, хэш поля сверяется со строками `sum`. В отчёте — раздел 7: игра, мест, люди (ники из `join … bot=0`), матч, тиков прогнано, сверки совпали из всего, тик первого расхождения, доигран ли матч. Журнал толпы старого формата (без `roster`) — строка «журнал без команд». CLI печатает число прогнанных боёв толпы, если они есть. Метрики игрока по прогону боя толпы — следующий шаг, по ним снимается манера игры для бота «как Дима».

## План тестирования

Сервер и клиент не меняются — их слои пусты. Инструмент проверяется через точку входа (функция, которую зовёт CLI: папка → отчёт и JSON) на синтетических журналах и на настоящем журнале со стенда e2e.

### Пакет `analysis` (Vitest, node)

Синтетические журналы собираются в тесте построчно в формате `game-log.md` (`logFixture.ts`); геометрия берётся с настоящих карт; каждый сценарий идёт через `analyzeLogs` на временной папке.
