# Тех-дизайн конкретных реализаций

Документы по отдельным фичам и подсистемам. Структура: `impl/<область>/<фича>.md`, где область — `backend`, `frontend`, `infra`. Фича, затрагивающая несколько областей, кладётся в область основной работы и ссылается на остальные.

Документ фичи содержит: что делает, контракты (сообщения протокола, таблицы, API), ключевые файлы кода и раздел «План тестирования» — сценарии с ожидаемым результатом и крайние случаи по трём слоям (сервер, клиент, сквозной прогон), с отметкой, что автоматизировано, а что прогоняется агентом вручную. План пишется до кода (ADR `tests.md`). Общие принципы не повторяются — ссылка на `tech/base/`.

| Документ | Что описывает |
|---|---|
| [backend/protocol.md](backend/protocol.md) | Бинарный протокол клиент ↔ сервер, подтверждение ввода, квантование |
| [backend/duel-server.md](backend/duel-server.md) | Сервер дуэли: комнаты, фазы, тик, тесты |
| [frontend/duel-client.md](frontend/duel-client.md) | Клиент дуэли: предсказание, интерполяция, ввод, рендер, HUD |
| [frontend/touch-controls.md](frontend/touch-controls.md) | Сенсорное управление: два плавающих стика, перевод в действие, план тестирования |
| [infra/deploy-proto.md](infra/deploy-proto.md) | Выкладка пробы на машину в Милане: Caddy, systemd, скрипты |
| [infra/android-app.md](infra/android-app.md) | Android-приложение: оболочка Capacitor, сборка APK в Docker, раздача по QR |
