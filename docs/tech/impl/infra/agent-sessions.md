# Сессии агентов: хуки, посадка, реестр

Как устроен процесс параллельных сессий из [исследования parallel-sessions](../../../research/parallel-sessions.md). Процесс исполняет код: хуки Cursor и Codex, одна команда посадки и хуки git. Агент держит в голове три правила, всё остальное ему подсказывают хуки в момент, когда это нужно.

## Что знает агент

Три строки в `AGENTS.md`, раздел «Сессии»:

1. Правки — только в рабочей папке, которую назвал хук. Основная папка `../tanks` — только для чтения.
2. Довести работу — `npm run land`: посадка в `main`, выкладка, проверка, уборка. Её вывод говорит, что делать, если посадка остановилась.
3. Нужен оператор — последняя строка ответа `Жду тебя: <вопрос>`.

Сообщения хуков — обязательные инструкции, не советы.

## Состав

| Часть | Где | Что делает |
|---|---|---|
| Пакет `session` | `packages/session` | Реестр под замком, карточки, аренды, рабочие папки, посадка, доска, ядро хуков. TypeScript, Node запускает исходники напрямую (стирание типов в Node 26), сборки нет |
| Хуки Cursor | `.cursor/hooks.json` | Переходник событий Cursor к ядру хуков |
| Хуки Codex | `.codex/hooks.json` | Переходник событий Codex к тому же ядру |
| Хуки git | `tools/githooks/`, `core.hooksPath` | Запрет коммита в основной папке и пуша в `main` мимо посадки — для любого инструмента |
| Настройка папки | `.cursor/worktrees.json` | `npm run session -- setup`: та же настройка для папок, созданных самим Cursor |
| Замок выкладки | [deploy-local.sh](../../../../deploy/deploy-local.sh) | `flock` на сервере: вторая выкладка ждёт первую |
| Доска | `npm run board` | Локальная страница со всеми сессиями |

Хуки запускаются из основной папки, поэтому работает версия из `main`: правка хуков вступает в силу после её посадки.

## Реестр

Папка `$(git rev-parse --git-common-dir)/agents/` — общая для основной и всех рабочих папок, вне репозитория.

| Файл | Что внутри |
|---|---|
| `lock` | Замок реестра: номер процесса и время. Держится на одно «прочитать, изменить, записать»; занят — ждать и повторять; процесса владельца нет — снять |
| `sessions/<имя>.json` | Карточка сессии |
| `leases/<ресурс>[.<слот>].json` | Аренда: сессия, цель, срок |
| `events.log` | Журнал переходов состояний — для доски и ревизии |

Писать в реестр может только пакет `session`.

**Карточка:** имя (`s-<4 знака номера чата>`, оно же имя ветки и папки `../tanks-<имя>`), название задачи (первое сообщение оператора, 80 знаков), номера чатов Cursor и сессий Codex, состояние, вопрос к оператору, последний ответ агента, тронутые файлы, занятые порты, время последней активности. Все поля заполняют хуки и посадка; агент карточку не пишет.

**Состояния:** `открыта` (чат есть, правок нет), `работает`, `ждёт оператора`, `ждёт ресурса`, `сажает`, `выложено`, `закрыта`.

## Хуки

Ядро получает событие в общем виде (начало сессии, перед действием, после действия, сообщение оператора, ответ агента, конец хода, конец сессии) и возвращает решение. Переходники переводят форматы: Cursor — `permission`, `agent_message`, `updated_input`, `followup_message`, `additional_context`; Codex — `permissionDecision`, `decision: "block"`.

| Событие (Cursor / Codex) | Что делает |
|---|---|
| `sessionStart` / `SessionStart` | Карточка `открыта` по номеру чата |
| `beforeSubmitPrompt` / `UserPromptSubmit` | Первое сообщение — название задачи. Карточка в `ждёт оператора` → `работает`, вопрос снимается |
| `preToolUse` на запись файла (`Write`, `StrReplace`, `Delete`, `EditNotebook` / `apply_patch`) | Путь в основной папке — отказ; у сессии нет рабочей папки — создаётся. Сообщение агенту: путь папки и ветка, «повтори правку там». Путь в папке другой сессии — отказ с её названием. Своя папка — разрешено, файл — в карточку |
| `preToolUse` на `Shell` / `PreToolUse` на `Bash` | Таблица команд ниже |
| `beforeMCPExecution` на `chrome-devtools` | Закрыть, выбрать или перейти можно только во вкладке, которую открыла эта сессия; вкладки сессии хук запоминает по ответам `new_page` |
| `postToolUse` / `PostToolUse` | Время активности, продление своих аренд. Файл, который правит ещё и другая работающая сессия, — подсказка агенту с её названием |
| `afterAgentResponse` / последний ответ в `Stop` | Последний ответ — в карточку; строка `Жду тебя:` — вопрос |
| `stop` / `Stop` | Решение о конце хода (ниже) |
| `sessionEnd` / `SessionEnd` | Отметка «чат закрыт»; непосаженное остаётся на доске |
| `subagentStart` | Саб-агент привязывается к карточке родителя и работает в его папке |

**Команды оболочки:**

| Команда | Решение |
|---|---|
| `git commit`, `merge`, `rebase`, `reset`, `checkout`, `switch`, `stash`, `add` в основной папке | Отказ, путь своей папки |
| `git push` в `main`, `deploy/deploy.sh` | Отказ: «посадка и выкладка — `npm run land`» |
| `npm run test:e2e`, `test:coverage`, `swarm`, `fx-sheets` | Команда оборачивается в `npm run session -- with heavy -- <команда>`: обёртка ждёт один из двух тяжёлых слотов, держит его на время команды и отпускает |
| `emulator -avd …` | Дописываются `-read-only -port <свободный чётный 5554–5682>`, берётся тяжёлый слот; порт и адрес `emulator-<порт>` — в карточку |
| `adb -s <серийник телефона оператора>` | Обёртка с арендой `phone`; телефон занят — отказ с названием сессии и сроком |

**Конец хода:**

1. Оператор остановил ход — ничего не делать.
2. В ответе есть `Жду тебя:` — карточка `ждёт оператора`, уведомление macOS (`osascript`) с вопросом.
3. Рабочей папки нет или в ней всё посажено — ничего не делать.
4. В рабочей папке непосаженное (незакоммиченное или коммиты вне `origin/main`) — агенту уходит следующее сообщение: что не посажено, «доведи до `npm run land` или закончи строкой `Жду тебя:`».
5. После трёх таких сообщений подряд — карточка `ждёт оператора` с вопросом «остановилась с непосаженным кодом», уведомление.

Хуки при сбое пропускают действие (поведение Cursor по умолчанию). Страховка от их сбоя — хуки git и ревизия сессий.

## Посадка: `npm run land`

Одна команда из рабочей папки. Останавливается с коротким выводом: что случилось и что сделать. После исправления агент запускает её снова, она продолжает с нужного шага.

1. Незакоммиченное — стоп со списком файлов.
2. Аренда `landing` (40 минут, продлевается по ходу). Занята — ждать.
3. `git fetch`; свежий `origin/main` в ветку: перестройкой поверх `main`, если в ветке до 10 коммитов, иначе слиянием `main` в ветку. Конфликт — стоп: список файлов и чьи коммиты в `main` их тронули. Агент решает конфликт, сохраняя оба намерения, и запускает `land` снова.
4. Документы задачи: ветка меняла код, а `state.md` текущей задачи не тронут — стоп: «допиши `state.md` поверх свежего текста».
5. Проверки: `typecheck`, `lint`, `test:coverage`; `test:e2e`, если тронуты `packages/client`, `server` или `shared`. Тяжёлые — в тяжёлом слоте. Упало — стоп с хвостом вывода.
6. `git push origin HEAD:main` с отметкой посадки для хука git `pre-push`. Отклонён — `main` ушёл вперёд, к шагу 3.
7. Выкладка, если тронут код сервера, клиента, `shared` или `deploy/`: `deploy/deploy.sh`, ожидание `/healthz`, сверка коммита в `/opt/tanks`, отметка выкладки на дашборде Grafana.
8. Аренда отпускается, карточка `выложено`, рабочая папка и ветка (локальная и на GitHub) удаляются, основная папка подтягивается `git pull --ff-only`.

Проверку фичи на проде (браузер, `debugState()`, ряд «Сервер: ОК?») агент делает после посадки по скиллу `develop`. Найденная ошибка — новая правка и новая посадка.

## Рабочая папка

- Создаёт её хук при первой правке: `git worktree add -b <имя> ../tanks-<имя> origin/main`, затем `npm run session -- setup`.
- Настройка: `node_modules` — копия папки основной с клонированием файлов APFS (`cp -c -R`, без лишнего места на диске), сборка `shared` в фоне. Пока сборка идёт, команды, которым нужен `dist`, ждут её через обёртку.
- Подтягивание `main` при возобновлении: хук сообщения оператора сравнивает ветку с `origin/main`; отстала больше чем на 10 коммитов — подсказка агенту «подтяни `main`: `npm run session -- sync`».

## Хуки git

`core.hooksPath` указывает на `tools/githooks/`, это ставит `npm run session -- setup`.

- `pre-commit` — отказ, если коммит идёт в основной папке.
- `pre-push` — отказ на пуш в `main` без отметки посадки.

Они ловят и Codex, и скрипты, и случайный пуш руками.

## Доска

`npm run board` — страница на `http://localhost:7700`, обновляется сама. Сверху — сессии в `ждёт оператора`: название, вопрос, сколько ждёт, команда «подхватить». Ниже — работающие, ждущие ресурса, аренды со сроками, карточки без активности дольше суток и сироты — рабочие папки и ветки без карточки. Оформление — палитра и шрифты игры.

Подхватить сессию — `/adopt <имя>` в любом новом чате (`.cursor/commands/adopt.md`): номер нового чата добавляется в карточку, агент читает её, последний ответ и стенограмму прошлого чата и продолжает в той же папке.

## Изменения в правилах и скиллах

- `AGENTS.md` — раздел «Сессии» из трёх строк выше.
- ADR [process.md](../../../adr/process.md) — коммиты в свою ветку, посадка в `main` и выкладка по процессу без отдельной просьбы.
- Скилл [develop](../../../../.cursor/skills/develop/SKILL.md) — последний шаг «Посадка: `npm run land`» и короткий раздел «Конфликт при посадке»; пункт о разрешении коммитов уходит.
- Скилл [current-task](../../../../.cursor/skills/current-task/SKILL.md) — `state.md` дописывается при посадке (`land` напоминает), подтверждённые решения — сразу в `decisions.md` своей ветки; в `.gitattributes` — `decisions.md merge=union`.
- Скилл [session-audit](../../../../.cursor/skills/session-audit/SKILL.md) — начинает с реестра, стенограммы — только для сирот.

## Тесты

Пакет `session` — тесты Vitest рядом с кодом:

- реестр: два процесса одновременно меняют карточку, ни одна запись не теряется; замок упавшего процесса снимается;
- аренды: истечение, продление, слоты;
- ядро хуков: таблицы решений по событиям на примерах входа Cursor и Codex;
- посадка: на временном репозитории с «удалённым» репозиторием-копией — конфликт, отклонённый пуш, пропуск выкладки для документов.
