# Бой с ботами и свои алгоритмы

Второе направление. Основа уже существует в `tank-arena`: бот — JS-модуль с функцией `tick(state) → {throttle, turn, turretTurn, fire}`, который каждый тик видит полное состояние поля. Есть шесть сильных ботов и два спарринг-бота, песочница в Node и просмотрщик в браузере.

## Две части

**Человек против бота.** Игрок заходит в бой, где часть танков — боты. Нужны уровни сложности.

**Свой алгоритм.** Игрок загружает `bot.js`, бот играет в турнирах против чужих ботов, есть таблица. Это формат Robocode / Screeps: соревнование программистов, а не реакции.

## Ключевой факт из исследования `tank-arena`

Человек против ботов участников играть не может: снаряд летит полсекунды, реакция человека 0,25 с, бот видит скорость и направление цели точно и без задержки. Даже Манекен (бот из восьми строк) — на уровне человека. Отсюда: ботам для игры с людьми нужны искусственные ограничения — задержка реакции, шум в прицеле, ограниченный обзор. Уровни сложности — это степень ограничения, а не качество алгоритма.

## Что меняется в архитектуре

- Бот исполняется на сервере в изолированной песочнице (в `tank-arena` — Web Worker в браузере зрителя; в онлайн-игре зритель не может быть судьёй).
- Лимит времени на ход (50 мс в `tank-arena`) сохраняется; бот, не уложившийся в лимит, повторяет прошлую команду.
- Контракт бота (`tick`, `init`, `stats`, вид состояния) сохраняется совместимым с `tank-arena`, чтобы существующие боты работали как контент.

## Что не решено

Формат пользовательских ботов в онлайне: загружаемый файл против редактора на сайте; ограничения на размер и зависимости; защита сервера от вредоносного кода. Решается при переходе к направлению, не в MVP.
