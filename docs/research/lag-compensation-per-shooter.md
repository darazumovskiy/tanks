# Лаг-компенсация по отставанию каждого стрелка

Вопрос: как сделать, чтобы лаг-компенсация ([shot-lead.md](../tech/impl/backend/shot-lead.md)) возвращала стрелку с плохой сетью столько, сколько он реально отстаёт, не ломая прицел игрокам с хорошей сетью и не перекладывая лишнего на жертву. Тема отложена до живых игроков: проверить её можно только A/B-тестом на людях с настоящим пингом.

## Проблема

Стрелок целится в картинку из прошлого, а сервер проверяет попадание в настоящем. Разница между ними — отставание стрелка:

- полный пинг — путь команды до сервера и снимка обратно;
- запас картинки чужих — на ровной сети 2 тика (66 мс), со сглаживанием сети на неровной связи до 9 тиков (300 мс), [net-smoothing.md](../tech/impl/frontend/net-smoothing.md);
- ожидание команды в очереди сервера — 1–3 тика, со сглаживанием на пачках до 6.

На пинге 60 мс и ровной сети это около 5 тиков, на пинге 100 мс — 6–8, на ночной сети телефона со сглаживанием — 15 и больше.

Сейчас компенсация — одна цифра на сервер для всех людей: снаряд рождается на `SHOT_LEAD_TICKS` тиков дальше по полёту. Проба на стенде — 2 тика: они никогда не больше отставания любого человека, потому что запас картинки не бывает меньше 2 тиков ([high-ping.md](high-ping.md), «Компенсация для медленных снарядов»). Цена этой безопасности — компенсация покрывает от трети отставания на хорошей сети до долей на плохой. На стенде с ночной сетью и сглаживанием компенсация в 2 тика не ощущается: она теряется на фоне 8–9 тиков запаса картинки.

Одна цифра больше 2 бьёт по игрокам с отставанием меньше неё. Их снаряд долетает до цели раньше, чем рассчитывал стрелок, и проходит перед врагом, в которого прицелились правильно. Сильнее всего это задевает игроков рядом с сервером.

## Идея

Компенсация каждого выстрела — отставание этого стрелка в момент выстрела, но не больше предела:

- **Пинг** сервер уже меряет сам.
- **Запас картинки чужих** знает только клиент: он присылает его вместе с командой. Без сглаживания запас — постоянные 2 тика.
- **Ожидание в очереди** сервер видит сам — сколько тиков команда с огнём пролежала в очереди.
- **Предел** защищает жертву, а не стрелка: компенсация на N мс значит, что в жертву попадают, когда на своём экране она уже N мс как ушла. Предел нужен и против обмана: клиент, приславший завышенный запас, получит не больше предела. Образцы — `sv_maxunlag` в Source (CS:GO — 200 мс), Valorant — 140 мс ([high-ping.md](high-ping.md), «Как это решают другие»). На стенде лаг-компенсации `/?lab=lag` оператор выбрал как терпимую цену для жертвы 80 мс.

Догон снаряда ложится на это без смены устройства: N уже живёт на снаряде, а не на цели. Меняется только источник N — вместо правила игры число каждого выстрела.

Что меняется по слоям:

| Слой | Изменение |
|---|---|
| Протокол | Команда с огнём несёт запас картинки клиента |
| Движок | N догона — у выстрела, а не в правилах игры; правило игры — только предел и выключатель |
| Сервер | N = пинг + запас картинки + ожидание в очереди, в тиках, не больше предела |
| Клиент | Предсказание своего снаряда — с N своего выстрела: клиент знает свой запас и пинг, сервер подтверждает своё N в снимке, и снаряд поправляется на разницу |
| Журнал | N каждого выстрела — в строке выстрела: прогон журнала без него не повторит бой |
| Анализатор | Меткость по полосам отставания стрелка; попадания, полученные жертвой, по величине компенсации стрелка |

Сложность для агента — M.

## Почему не сейчас

Решение о пределе — это баланс между стрелком с плохой сетью и его жертвами. Почувствовать его может только смешанная толпа: игроки с хорошей и плохой сетью в одном бою. Сейчас постоянных игроков нет, а оператор, играющий сам с собой через стенд с плохой сетью, — одновременно и стрелок, и жертва с одной и той же искусственной сетью. Такой опыт не говорит, как бой ощущается для толпы.

## Как мерить: A/B-тест

Игроки делятся на группы по номеру устройства, группа держится между играми. Варианты:

- A — компенсация одной цифрой 2 тика, как сейчас;
- B — компенсация по отставанию стрелка с пределом 80 мс;
- C — то же с пределом 150 мс.

Группа — у стрелка: в одном бою встречаются игроки разных групп, и жертва получает снаряды с любой компенсацией.

Метрики по журналам:

- меткость по движущимся целям в полосах пинга стрелка — до 60, 60–100, 100–150, больше 150 мс; цель варианта — чтобы меткость плохих полос подтянулась к хорошей, не задев хорошую;
- доля попаданий по жертве, полученных с компенсацией больше 100 мс, — оценка того, как часто жертву бьют «уже за стеной»;
- длина сессий и возврат игроков по группам и полосам пинга.

## Условие входа

- Живые игроки с разной сетью, в том числе с телефонов, — столько, чтобы в каждой группе и полосе пинга набирались сотни выстрелов в день.
- Сглаживание сети включено на боевом сервере: без него запас картинки постоянный, и компенсация по отставанию сводится к компенсации по пингу.
- Деление на группы по номеру устройства и разбор метрик по группам в анализаторе ([log-analysis.md](../tech/impl/backend/log-analysis.md)).
